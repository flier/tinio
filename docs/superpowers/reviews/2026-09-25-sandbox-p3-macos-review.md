## Security

### SEC-01 — Read-only root gains a read-write hole when the state directory is spelled the way the kernel will see it — **fail-open (MEDIUM)** — **[FIXED — r3, uncertified: four literal/resolved pairings through the shared `resolved_path`; the files moved during that pass]**
- **Files**: `crates/tinio-cli/src/sandbox/mod.rs:759-772` (`refuse_in_root_state_dir`), `:720-728` (`sandbox_request`), `crates/tinio-util/src/path.rs:83-104` (`path_contains`), `crates/tinio-sandbox-macos/src/profile.rs:537-558` (`with_canonical_paths`, push at `:549-552`), `crates/tinio-sandbox-macos/src/launch.rs:182` (`launch::confine` renders that set).
- **Finding**: both guards decide with `path_contains`, which on unix is a **literal component comparison — no canonicalisation, no symlink resolution**. The exposure set that actually gets rendered *does* carry canonical forms: `with_canonical_paths` appends `canonicalize(host)` for every exposure **preserving its access**, and `launch::confine` renders that set. Failure scenario (no operator-created symlink needed; the code's own docs call `/tmp` → `/private/tmp` and `$TMPDIR` → `/private/var/folders` the normal macOS condition): `tinio server /tmp/ro-root --read-only --sandbox` with `TINIO_STATE_DIR=/private/tmp/ro-root/.tinio` (the spelling any tool emitting `realpath`/`pwd -P` produces — and the read-only path *forces* an explicit `TINIO_STATE_DIR`, `mod.rs:807-825`). The guard sees `is_within([private,tmp,ro-root,.tinio], [tmp,ro-root])` → false → passes; `sandbox_request` exposes it `ReadWrite`; the profile then renders `E0=/tmp/ro-root` RO, `E1=/private/tmp/ro-root` RO, `E2=/private/tmp/ro-root/.tinio` **RW**. Rules are additive and a read-write `subpath` rule beats a read-only one, so the confined server may write inside a root the operator asked to be read-only — while the **unconfined** run of the same command line is refused ("read-only mode cannot serve a root that holds the state directory"). Confinement is therefore strictly weaker here. The same hole opens with a symlinked root or state dir (a symlinked data volume is common on macOS). The guard's own doc (`mod.rs:743-747`) justifies the literal comparison with "a guard decided over canonical forms would be deciding about paths the exposure set never sees" — a premise that is false on macOS, where the exposure set sees both spellings.
- **Fix**: decide the guard on the canonical pair (or on both spellings), which the current doc argues against.
- **Round 3**: fixed (`refuse_in_root_state_dir` `:840-853` → `state_dir_in_root` `:868-888` compares four pairings through the shared `tinio_util::path::resolved_path`; the recorded exploit is caught, the unit leg `:1373-1423` drives both spellings plus a must-stay-open sibling, and guard and render share one derivation) — **uncertified because those files were edited during the pass**, and the fix's premise is contradicted in the other direction by round 3's SEC-05 (a state dir that is an *ancestor* of the root is still exposed read-write over it).
