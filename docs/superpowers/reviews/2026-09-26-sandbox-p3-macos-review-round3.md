## Security — new findings

### SEC-05 — A state directory that *contains* the served root is exposed read-write over it — **fail-open (MEDIUM-HIGH)**, unrecorded — **[OPEN]**
- **Code path**: `sandbox_request` (`crates/tinio-cli/src/sandbox/mod.rs:764-772`) reads "not `path_contains(state_dir, root)`" as "outside the root" and takes the `else` at `:769`, adding `expose(state_dir, ReadWrite)`. Containment is tested in one direction only; a state dir that is an **ancestor** of the root is neither contained nor disjoint, and the branch treats it as disjoint. `with_canonical_paths` renders both exposures and the template writes one rule per exposure (`profile.hbs:3`); SBPL rules are additive and a `subpath` covers its own subtree, so the read-write rule swallows the read-only one.
- **Failure scenario**: `TINIO_STATE_DIR=$HOME tinio server $HOME/data --read-only --sandbox` — `resolve_state_dir` (`crates/tinio-cli/src/resolve/locate.rs:197-215`) takes the override verbatim, `refuse_in_root_state_dir` asks only "is the state dir inside the root" → false, and `refuse_underived_state_dir` does not fire (the dir *was* named). The confined child then holds `file-read* file-write* (subpath "/Users/<u>")` — read-write over the whole home directory, including the `$HOME/data` the operator asked to be read-only. The CLI's own refusal text ("set `TINIO_STATE_DIR` outside the served root") reads as "a parent is fine" to the operator shown it.
- **Cross-platform**: the same branch feeds the other two arms — Linux mounts exposures in list order (`crates/tinio-sandbox-linux/src/plan.rs:164-206`), so a later RW bind at the ancestor covers an earlier RO bind, and `validate_exposures` (`crates/tinio-sandbox-linux/src/enter.rs:214-240`) refuses only missing/un-mirrorable paths; Windows' exposure ACE is inheritable (`(OI)(CI)M`, design §6), so the ancestor grant reaches the root (by rule rather than by trace).
- **Recorded?** No. The design assumes nested-or-disjoint: §9 (`design.md:471`) "the state directory is `TINIO_STATE_DIR` or `<home>/.tinio/roots/<hash>/` — **outside the served root**", and §4's table row "`<state dir>` — only when it lies outside the served root". The guard's own doc (`:798-802`) states the rule as "its `else` branch only ever *adds* an exposure for a path judged outside the root" — the judgement is the bug.
- **Fix shape**: refuse read-only when the *root* is inside the state dir (the symmetric `path_contains(root, state)`), or expose the state dir with every path under the root removed.
