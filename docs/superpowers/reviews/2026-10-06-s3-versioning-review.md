**Scope**: the design `docs/superpowers/specs/2026-10-03-s3-versioning-design.md` and its three plans (`2026-10-03-s3-versioning-p1-block-engine.md`, `-p2-versioned-store.md`, `-p3-s3-surface.md`) against the landed tree (`eb4b28e7` block engine, `ee9896a6` versioned store, `ba5004a6` S3 surface).

## Findings and dispositions

### Important

- **Read-only mode wrote inside the served root** (plan 3's one substantive defect): the startup repair's state-dir stages (`repair_tmp`, `repair_block_residue`, `repair_multipart_orphans`, `repair_orphan_upload_dirs`, `repair_buckets`) ran in every mode while the amended read-only run's state dir **is** `<root>/.tinio`, so a read-only start deleted residue inside the root — contradicting FR-023's promise and its own rationale, and the old test pinned a layout read-only can no longer produce. **Fixed**: `FsCleanup::repair` skips every state-dir-writing stage unless dry-run (the doctor's read-only report still walks them), the test rebuilt on the real shape, and a dry-run leg pins the report-only behavior (`crates/tinio-fs/src/cleanup.rs`).
- **The sweep materialized every version row twice per pass, under the bucket lock, even with both retention keys unset**: `bucket_history` (retention + gauge) plus `live_blocks` (a second full decode), then the whole block-store walk inside the lock. **Fixed**: one read transaction now yields the live set, the retirement decisions and the gauge count in a single decode (retired rows' blocks excluded so the same pass reclaims them), the plan+expiry stay under the lock, the walk moved outside it, and the removal phase re-reads the live set under the lock and re-checks every candidate (`crates/tinio-fs/src/sweep.rs`). The held window is now (decode + expiry) + (unlinks); a `LiveSet` and one page of candidates are the walk's memory.
- **One undeletable block aborted the whole pass**: `Store::sweep` propagated a `remove` failure, and `sweep_once` returned early, skipping the orphan-subtree, temp and multipart sections and every later bucket. **Fixed**: per-entry failures are logged and counted in `SweepReport::failed`, per-bucket failures warn and the other buckets run, and `sweep_once` runs all five sections before reporting the first error (`crates/tinio-blob/src/sweep.rs`, `crates/tinio-fs/src/sweep.rs`).
- **`ListObjectVersions` memory amplification**: the walk buffered each covered key's **entire** history (a single key with 10⁶ versions was enough), and the client-controlled `max-keys` had no ceiling. **Fixed (bounded)**: each key's rows are read newest-first and capped at `max_keys + 3` (the key a version-id-marker resumes inside is read streamed from the marker down), with the truncation guarantee argued in the code and pinned by a 30-version, 2-per-page walk; the follow-up wave below then added the listing's 1,000-page ceiling and the window's total row budget, so the transient is a page's entries plus one bounded window (`crates/tinio-fs/src/version/list.rs`).
- **`PutBucketVersioning` was not serialized with the write path**: every write reads the state under the bucket mutation lock, but the flip took no lock. The mechanism was confirmed; the coordinator **downgraded the impact** (every interleaving is linearizable as "the write before the state change", so no client-visible guarantee breaks) and the fix still landed as a determinism improvement: the flip now takes the same lock, pinned by a lock-parking test (`crates/tinio-fs/src/backend/version.rs`, `crates/tinio-fs/src/version/tests.rs`).
- **A versioned write could answer an unresolvable version id** (I7): `record_committed` was best-effort, so a failed metadata row write left the client holding an id that answers `NoSuchVersion`, with only a log line. **Fixed**: `record_committed` returns its result, and a version-creating write **fails** on a row-write failure (the file stays and reads as the null version — the out-of-band shape), while an unversioned write keeps FR-022's best-effort rule; pinned on a read-only handle (`crates/tinio-fs/src/backend/objects.rs`, `backend/tests.rs`).
- **The fs block store has no capacity ceiling** (unlike `tinio-mem`'s `max_total_bytes`), with retention defaulting to keep-everything. **Resolved by observability** in the follow-up wave below (size gauge + `[s3] block_bytes_warn`); a hard cap remains unbuilt by choice.

### Minor (all fixed unless noted)

- `expect_exact` forwarded an overshooting chunk whole (the short side was guarded): it now ends the stream with `InvalidData`, and `BlobRef::new`'s zero-length rule keeps the arithmetic total (`crates/tinio-blob/src/engine.rs`).
- `fan_out_dirs` filtered on the name only, so a *file* named like a fan-out directory made every walk — and so every sweep — error until a human removed it: the entry type is checked now (`crates/tinio-blob/src/local.rs`).
- The symlink asymmetry (reads follow a link at a canonical block path; the walk lists regular files only) is now documented at the store's module doc — the two halves are deliberate and must not be "fixed" apart.
- A failed unlink on the dedup path turned a publish that already found its block into an error: it warns and answers `Existing` now.
- `LiveSet::from_blobs` allocated one `Vec` per blob: built in place.
- The version listing cloned its whole accumulated entry vector for every truncation probe and cloned each emitted entry twice: `version::paginate` now takes `&[Entry]` (the probe borrows) and its cursor keeps the key + version-wire pair instead of a second `Entry` clone — both backends' listings lose the probe clone (`crates/tinio-core/src/version.rs`, `crates/tinio-fs/src/version/list.rs`, `crates/tinio-mem/src/version.rs`).
- A control character in a `versionId` could reach the XML error body (validation is length-only; quick-xml escapes markup, not control bytes): the reflected values (`NoSuchVersion`, `InvalidVersion`, `NoSuchUpload`) now render control characters as `U+FFFD`, pinned by a test (`crates/tinio-server/src/backend/errors.rs`).
- Two internal refusals (the supersede row-conflict guard and the materialize-published-none case) echoed bucket/key/sequence to clients: the context now goes to the log and the client answers the family's generic internal error (`crates/tinio-fs/src/version_adapter.rs`, `backend/version.rs`).
- The marker `405` and the marker-disclosing `404` lost their `Content-Type` (s3s 0.17's `serialize_error` replaces the response header map with the error's): both now carry `application/xml`, with tests that fail without the fix (`crates/tinio-server/src/backend/versioning.rs`).
- No capability-layer test drove the three versioning rows with the toggle off: added, together with its on-complement (`crates/tinio-server/src/capability.rs`).
- The batch `Deleted` contract sentence said a named marker reports "no marker fields"; the code (and the single-object DELETE) report the marker triple: the sentence now says so (`specs/001-s3-local-server/contracts/s3-surface.md`).
- A spliced doc comment in the e2e step definitions was repaired (`crates/tinio-e2e/tests/steps/common.rs`).
- `cleanup.rs`'s `Self::verify_bucket_blocks` link named a function that exists only in the plan (`check_bucket_blocks` now); note that neither `cargo doc` nor `cargo doc --features versioning` catches it — the item is private, and only `--document-private-items` lints it (the doc gate's known cfg/private blind spot).
- `Current::seq`'s doc claimed the null version starts at sequence 1; the shared policy records 0 while 0 is free: corrected (`crates/tinio-version/src/ports.rs`).
- `tinio-fs`'s feature-off arm compiled by no CI leg (its self dev-edge unifies `versioning` back on for test targets): a `cargo hack check --package tinio-fs --each-feature` step landed, `tinio-mem`'s twin followed (it had the same blind spot), and `docs/tests.md` names the classes and the leg again (`/.github/workflows/ci.yml`).

- A corrupt stored identity self-healed to the *null version* (a meaningful value): the row decode now validates the id element — `null` or a well-formed id — and a corrupt one reads as a missing row, pinned with a corrupt-row fixture (`crates/tinio-store/src/version.rs`).
- The bundled `tinio-util`/`fsutil` extraction shipped inside plan 1's commit with no plan-1 record: recorded in the plan's header note (the runtime dependency, the manifest drift: `hex` dropped, `smart-default` added).

## Residuals: status after the follow-up wave (T157, 2026-10-06)

Every residual this round recorded was taken up the same day, on the operator's choices:

- **The fs block store's missing cap**: resolved by observability — the sweep's walk now reports the store's total bytes (`SweepCandidates::bytes_total` → `Summary::block_bytes` → the `tinio_storage_block_bytes` gauge) and the new `[s3] block_bytes_warn` key logs a warning above a configured threshold. No hard cap was added; the design's Risk bullet says so.
- **The version listing's window bound**: resolved — `ListObjectVersions` answers `max-keys` as at most 1,000 (AWS's documented maximum; `contracts/s3-surface.md` carries the sentence), and the row walk adds a per-window total budget of `WINDOW_KEY_ROWS` per-key caps, leaving a key it cannot read at its full cap to the next window — whose fresh budget reads it at the cap, which guarantees the page fills and truncates. Memory is one page's entries plus one window's bounded rows.
- **The sweep's removal-phase lock hold**: resolved as the design's second sanctioned guard — the mark epoch. A process-local version-reference epoch is bumped by every version-row commit inside the bucket mutation lock; the removal phase re-checks it under the same lock and defers the whole candidate set when a publish intervened. The walk stays lock-free; the lock now covers the epoch check and the unlinks.
- **The optional startup block verify**: built — a start that followed a crash (the startup repair actually cleared residue) spawns a background, report-only re-read-and-rehash of every versioned bucket's blocks, counted on `tinio_storage_blocks_corrupt_total` (the family the doctor's findings feed too).
- **The marker `Content-Type` assertion depth**: closed end-to-end — the cucumber journey asserts `content-type: application/xml` on the marker `404` and on a version-addressed `GET` of the marker (the new `405` journey leg), on both backends.
- **The write path's extra state read**: resolved — the versioning state and the key's sequence view now come from one point-read transaction (`state_and_seqs`), so a versioned PUT pays one redb read for the pair.

Trade-offs the wave introduces, recorded rather than hidden: a publish landing between a sweep's plan and its removal defers that pass's removals entirely (a block has no reverse index to re-check individually), so a continuously written bucket may reclaim on a slower cadence; the listing's 1,000 ceiling is a wire-contract change (documented in `contracts/s3-surface.md`); and the startup verify reads the whole block store once, in the background, only when the repair found crash residue.
- **`docs/tests.md`'s state-dir sentence and the CI feature legs** were restored/added as above; the compaction that dropped them (`ba5004a6`) is recorded in the design's GC bullet.
