# Design: S3 owner & ACL (authn/authz engine)

**Date**: 2026-09-05
**Status**: approved — brainstorming 2026-09-04/05 (user Q1–Q5, plus the user's crate/feature directive 2026-09-04)
**Scope**: tinio workspace, end-to-end — a new `tinio-auth` crate (SigV4 auth provider + ACL authorization engine), ACL domain types and wire codecs in tinio-core, shared-row extension in tinio-store (its first schema change after the shared-store table-layer plan lands), storage-contract owner/ACL parameters, tinio-server ACL operations + write-path ACL headers + Owner population + requester list filtering + `expected_bucket_owner`, tinio-config `[owner]`/`[users]`, unix object-file permission + ownership hardening in tinio-fs (new object files 0600 and bucket/prefix dirs 0700, additionally chowned to the owner's / bucket owner's mapped uid when a local-user mapping is configured), an `acl` Cargo feature gate plus a `Capabilities.acl` runtime toggle. Not touched: bucket policies (separate config storage + evaluation model), IAM/federated users, versioning (`list_object_versions`, `versionId` ACLs stay NotImplemented), Object Lock, SigV2 rules (s3s already handles v2 signatures once the secret is returned; kept enabled — see Decisions).
**Companion**: `2026-09-04-s3s-api-coverage-gap-analysis.md` (this plan closes its Tier-A ACL row and its "real vs echo" open question — user ruling: **real, enforced**).

## Background

- tinio has no owner/user concept today: `[auth]` is a single credential pair; `serve.rs` wires s3s `StaticAuth` (single pair, `InvalidAccessKeyId` for unknown keys, unsigned requests rejected); the e2e harness uses `DataPlane::new` (no auth — unsigned requests allowed, signed ones error since no provider).
- s3s 0.15 ships the two seams this plan needs:
  - **`S3Auth`** (`s3s::auth`) — one method, `get_secret_key(access_key) -> S3Result<SecretKey>`; s3s performs SigV4 (and v2) signature verification and sets `S3Request.credentials: Option<Credentials>` (`None` = anonymous).
  - **`S3Access`** (`s3s::access`, `S3ServiceBuilder::set_access`) — invoked before the route/handler with `S3AccessContext` (`credentials()`, `s3_path()` → root/bucket/object, `s3_op()` → operation name, `method()`, `headers()`, `extensions_mut()`). Enforced only when `set_auth` is also set; without it s3s's default allows all authenticated and denies anonymous. This is the single enforcement point — no per-`op_*` authz checks.
- All four ACL trait methods already default to 501 NotImplemented in s3s 0.15. The dto inputs carry `x-amz-acl` and `x-amz-grant-*` **pre-parsed** on every relevant surface: `PutBucketAclInput`/`PutObjectAclInput` (`acl`, `access_control_policy`, `grant_*`), and the write paths `PutObjectInput`, `CopyObjectInput`, `CreateBucketInput`, `CreateMultipartUploadInput` — so write-path ACL headers need no manual parsing. `Grantee.type_` is non-optional; `Owner { id, display_name }`, `Grant { grantee, permission }`, `Grants = List<Grant>`, `Permission` consts (`FULL_CONTROL`, `READ`, `READ_ACP`, `WRITE`, `WRITE_ACP`). No `CheckIfObjectExists` field in s3s 0.15.
- Storage rows (shared table layer, post-tagging shapes): `BUCKETS` `name → (created_at_nanos, tags_wire)`; `OBJECT_META` `(bucket, key) → (etag, size, mtime, file_identity, tags_wire, checksum_wire)`; `UPLOADS` `(bucket, upload_id) → (key, initiated_at_nanos, tags_wire)`. The established extension mechanism is tuple-arity extension + canonical wire-string elements, with **no schema version bump** (user ruling 2026-09-02 — additive changes carry no bump; `STATE_VERSION` stays 1) and self-healing row decode (invalid elements → `None`/default).
- Owner/ACL semantics source: the AWS ACL overview (canned ACL expansions, grantee types incl. the anonymous-upload special canonical ID `65a011a29cdf8ec533ec3d1ccaae921c`, permission meanings, the 100-grant cap, `BucketOwnerEnforced` note — tinio keeps ACLs enabled).

## Goal

1. **ACLs are real.** Grants are stored per bucket/object (fs + mem via the shared layer), echoed by GetACL, and **enforced before every route** — classic multi-user model: bucket owner = creator, object owner = uploader, owner retains implicit full rights, and ACLs gate non-owners and anonymous.
2. **Authn is real.** Configured identities: the existing `[auth]` pair becomes the root user; `[users]` adds signable principals. SigV4 verification is s3s's; tinio supplies secrets keyed on access key, unknown keys → `InvalidAccessKeyId`.
3. **Write-path ACL headers land.** `x-amz-acl` / `x-amz-grant-*` on PutObject, CopyObject, CreateBucket, CreateMultipartUpload, with the eight canned-ACL expansions per the AWS table.
4. **Owner is surfaced in listings and the ACL policy.** `Owner` elements in list v1/v2 entries, `list_buckets` output, and the ACL-policy `Owner` — GetObject/HeadObject return no Owner (s3s 0.15 dto has no such field; matches AWS); `list_buckets` returns only the requester's buckets; `expected_bucket_owner` is validated (403 `AccessDenied` on mismatch).
5. **Feature-gated, two layers:** a new `tinio-auth` crate + server `acl` Cargo feature (default on, in the `default` feature set alongside `multipart`/`copy`/`list-*`) for compile-time strippability, and `Capabilities.acl` (default on) for runtime toggling — the existing double-gate pattern (cf. `#[cfg(feature = "multipart")]` + the capability runtime gates).
6. **Legacy behavior preserved:** `DataPlane::new` (no auth) keeps today's semantics; pre-existing rows with no owner element evaluate as the configured default owner.

## Non-goals

- **Bucket policies / IAM.** ACLs are the only authorization model; policy engine, roles, and federation are out of scope. ACL-only authorization therefore treats ops that AWS guards by policy-only permissions as owner-only (see the matrix).
- **Email grantees** — rejected with 400 `InvalidArgument` (AWS deprecated email grants; s3s still models `email_address` — only for the rejection path).
- **Deny grants** — S3 ACLs have no deny semantics.
- **Object Lock / Veeam-class probes, `list_object_versions`, `get_bucket_policy*`** — remain NotImplemented; the ACL access check maps unknown operations to owner-only (default B below).
- **ACL caching** — per-request storage reads for ACL/owner evaluation are accepted at dev-local scale (two row reads for object ops, one for bucket ops — see Risks); no cache layer.
- **Full per-request impersonation** — no `seteuid`/setgid per request; the server runs privileged once and performs post-write chown, not per-call impersonation.
- **Group/gid models** — no OS-group mapping; the S3 group grants (AllUsers/AuthenticatedUsers/LogDelivery) do not map to OS groups.
- **Windows SID/ACL mapping** — no SID mapping; `local_uid` is rejected on Windows (config parse fails fast), and Windows keeps today's inherits-creating-user behavior.
- **SigV2 policy** — s3s verifies v2 signatures itself once the secret is returned; nothing to build.

## Decisions (locked 2026-09-04/05)

- **Enforcement model** (user Q1, custom): *add authn/authz — ACLs enforced*, not stored-and-echoed.
- **Principal model** (user Q4): *multi-user full* — signed principals map to configured users; bucket owner = creator; object owner = uploader; anonymous = the AWS special canonical ID `65a011a29cdf8ec533ec3d1ccaae921c` (used in enforced mode; AWS's own anonymous-uploader ID).
- **Owner identity** (user Q2): configurable `[owner] { canonical_id, display_name }` with defaults (canonical ID = the fixed 64-hex `hex(SHA-256("tinio"))` constant, display name `"tinio"`). The default owner is also the **lazy owner** for pre-existing rows with no owner element; no-identity write paths record an **empty** owner element (see the owner-recording ruling below — review B4, the lazy semantics must be uniform).
- **Write-path ACL headers** (user Q3): supported on all four write surfaces.
- **Sequencing** (user Q3 follow-up): this plan lands **after** the shared-store table-layer plan merges; the shared rows are extended once, here.
- **Separate crate + feature gate** (user directive, 2026-09-04): authn/authz engine in a new `crates/tinio-auth`; `tinio-server` depends on it optionally via the `acl` feature (added to `default`). Feature off ⇒ no S3Auth/S3Access wiring, the four ACL ops fall back to s3s's 501 defaults, ACL headers accept-and-drop, no owner resolution — storage still records rows with an **empty (lazy) owner element** and the default private ACL (the contract is feature-independent; the owner-recording ruling below).
- **Core types in tinio-core** (`acl` module): `OwnerId`, `Permission`, `Grantee`, `Grant`, `Acl`, wire codecs, validation — the storage backends persist them and must not depend on tinio-auth.
- **Owner recording rule** (write paths): owner = (1) signed user's canonical ID; (2) anonymous special ID in enforced mode; (3) **empty (lazy default owner)** under no-identity paths (`DataPlane::new`, feature-off) — review B4, 2026-09-05: explicit recording of the default owner was rejected because a later `[owner].canonical_id` change would orphan explicitly-owned rows (no matching identity — even the root gets 403) while lazy rows re-resolve; empty-wire keeps both classes consistent. The contract takes `owner: Option<&OwnerId>` (None = empty wire). Multipart: the CMU records owner + ACL; completion applies them (read **backend-internally** from the upload row, like tags — the server does not re-pass them at complete); the object owner is the CMU creator even if a different user completes. **PUT-overwrite replaces the owner element with the new uploader's ID and replaces the previous ACL** — the object is recreated, classic AWS semantics (grilling Q2, 2026-09-05).
- **Overwrite authorization** (review B1, 2026-09-05): AWS's WRITE semantics — "*WRITE permissions deny non-owners the ability to overwrite or delete existing objects*". Therefore PutObject/PostObject/CopyObject/CompleteMultipartUpload on a **destination key that exists** require P == O(destination object) or P == O(destination bucket); on a missing key, bucket WRITE suffices. Implemented as an existence head in the access check (an extra read on write paths; the TOCTOU window between check and handler is accepted and documented).
- **CopyObject ACL rule**: the copy takes the request's ACL headers or the default private ACL — never the source object's (AWS behavior); the copy's owner = the requester. Rename preserves owner and ACL.
- **Authorization matrix** (AWS-classic mapping table + implicit-owner rule) — see the matrix below. Two tinio choices where AWS semantics are policy-only and tinio has no policy engine:
  - *Default A*: object tagging and `get_object_attributes` allow the **object owner or the bucket owner** (recorded deviation: AWS requires bucket-policy permissions).
  - *Default B*: resolved operations the matrix does not map (currently-NotImplemented ops included) are **owner-only**, never anonymous — fail closed. Consequence: in enforced mode not-yet-Implemented ops answer 403 `AccessDenied` for non-owners instead of 501 (more AWS-true; the owner still sees 501). Truly unknown paths (unresolvable subresources) never reach the access check — s3s answers 501 "Unknown operation" first (no data exposed).
  - *Default C*: email grantees → 400 `InvalidArgument` (recorded deviation from legacy AWS acceptance).
- **Canned-ACL normalization**: the eight canned ACLs expand exactly per the AWS table (`private`, `public-read`, `public-read-write`, `authenticated-read`, `aws-exec-read`, `bucket-owner-read`, `bucket-owner-full-control`, `log-delivery-write`); `bucket-owner-read`/`bucket-owner-full-control` are ignored (treated as private) when specified on CreateBucket, per the AWS doc. `aws-exec-read` is **accepted but expands to the private default** (owner FULL_CONTROL; the EC2 grant is dropped) — grilling Q5, 2026-09-05: the EC2 group URI is undocumented (AWS records exactly three special-grantee URIs) and MinIO does not special-case it (no `aws-exec` in its Go sources), so the original "mirror MinIO's canned implementation" intent is unverifiable; the dropped grant has no semantic loss since EC2 can never be a tinio principal (recorded deviation). Canned + grant headers in one request → 400. s3s's `ObjectCannedACL`/`BucketCannedACL` are string newtypes, so any value parses — values outside the eight-name table → 400 `InvalidArgument` at the tinio-auth expansion layer. Canned expansion takes **both** the object owner and the bucket owner (review A6) — `bucket-owner-read`/`bucket-owner-full-control` add a grant referencing the bucket owner's ID, which the single-owner signature cannot express.
- **ACL wire format** (grant set): canonical sorted `grant1&grant2&…` where `grant = grantee_wire ',' permission_wire`; grantee wire = `id=` + 64-hex ID or `uri=` + RFC 3986 percent-encoded group URI, following the tags codec precedent. Validation: ≤100 grants (AWS cap), canonical ID 64 lowercase hex, group URI ∈ the three documented constants, permission ∈ the five. Invalid/over-cap wires self-heal to the default private ACL (owner FULL_CONTROL); the owner element self-heals to `None` (lazy default owner).
- **Grant display names are presentation, not identity**: rows store canonical IDs only; the server resolves display names from its identity map at response time (unknown ID → ID-only Owner, matching AWS's unknown-account shape).
- **`expected_bucket_owner`** validated in the access check against the bucket owner (row owner, or lazy default): mismatch (and the bucket exists) → 403 `AccessDenied`; missing bucket → the check passes through and the handler answers `NoSuchBucket`.
- **Put-ACL `Owner` mismatch is fail-closed**: an `AccessControlPolicy` body whose `Owner` does not match the row owner → 400 `InvalidArgument` (exact AWS parity to be verified against the AWS docs at implementation, recorded in the same style of verification note the doc uses elsewhere).
- **CreateBucket requires an authenticated principal** (enforced mode): anonymous 403 — a bucket needs a creator owner; AWS requires authentication for the op.
- **`list_buckets`** (enforced mode) returns only buckets whose owner is the requester; anonymous → 403 (AWS/MinIO behavior).
- **Fail-closed storage errors in the access check**: a storage error while evaluating a decision → `AccessDenied`. `NoSuchBucket`/`NoSuchKey` are **deny-first with three tiers** (grilling Q7; review B3, 2026-09-05): (1) P == bucket owner → pass through to the handler's 404/204; (2) P holds a bucket **READ** grant → pass through (AWS exposes existence to bucket readers — `aws s3 rm` idempotency relies on it; tier 2 is what makes tinio's posture a documented conservative posture, not "alignment"); (3) otherwise → 403 `AccessDenied` (no existence leak).
- **DeleteObjects enforcement is split, gate corrected** (grilling Q1; review B2, 2026-09-05): the access check enforces a **coarse gate — bucket owner or any bucket-ACL grant to P** (whole-op 403 for anonymous/unrelated) — not bucket-WRITE: a WRITE-gated whole-op 403 wrongly blocks per-key own-object deletes, and AWS has no bucket-level gate at all. The handler (`op_delete_objects`) performs the per-key owner/ACL check, emitting per-key `<Error><Code>AccessDenied</Code></Error>` entries for denied keys in a 200 response — AWS-style mixed results.
- **`Content-MD5` on the put-ACL operations** (grilling Q6, scoped grilling Q4): `PutBucketAcl`/`PutObjectAcl` require a `Content-MD5` header — three states per AWS (see §5): missing → 400 `InvalidRequest` (`"Missing required header for this request: Content-MD5"`), malformed (not a well-formed 16-byte base64 digest) → 400 `InvalidDigest`. **Committed scope**: presence + well-formedness only; digest-equality against the XML body is **not verifiable at the op** (s3s's deserializer consumes the body; `S3Request` retains no raw bytes for full-body ops) — recorded deviation (AWS verifies the digest → `BadDigest`); if implementation finds a retained body accessor, the equality check is added. PutObject's Content-MD5 stays unenforced (out of scope).
- **`/metrics` stays outside the ACL check** (grilling Q5): pre-route interception in `data.rs` is management-plane, unchanged; documented in the server module docs.
- **TOCTOU is an accepted dev-local risk** (no new mechanism): the pre-route access check and the handler mutation are not atomic — there is no cross-call storage transaction, and the server per-key locks (`S3Backend::conditional_put_locks`) are not reachable from `S3Access`. A concurrent overwrite/ACL change between check and mutation can act on stale authorization (e.g. DeleteObject deleting a just-overwritten object). Accepted at dev-local scale; revisited if tinio grows multi-instance or stronger guarantees.
- **SigV2 posture**: s3s verifies SigV2 by default (`enable_sig_v2` default true) and this plan keeps it enabled for old-client interop — a deliberate posture (weaker scheme accepted at dev-local scale), revisited if the threat model changes.
- **S3→OS user mapping** (locked 2026-09-05): `[users]`/`[owner]` may map a principal to a local unix uid via `local_uid`; after a file lands it is `chown`ed to the mapped uid, composing with the already-decided 0600/0700 modes. **Not** full per-request impersonation (no seteuid) and **not** metadata-only. Four locked design rulings:
  - **Mapping depth**: chown ownership mapping only — the server runs privileged (root or CAP_CHOWN), not per-call impersonation.
  - **Privilege model**: **hard validation at startup** — if any `local_uid` is configured but the process lacks chown privilege, startup fails with a config error (fail-closed; no silent degradation to server-user ownership).
  - **Platform**: **unix-only** — `local_uid` is rejected at config parse time on Windows (fail fast, consistent with the hard-validation posture); Windows stays as today (files inherit the creating user's ACLs).
  - **Directory ownership**: bucket dirs (and implicitly created prefix dirs within a bucket) are chowned to the **bucket owner's** mapped uid with mode 0700. Consequence: other mapped users cannot locally browse a bucket they don't own (the privileged server process is unaffected); isolation is total.
  - **Config-supplied map only**: the `OwnerId → uid` map comes from config, never from request data (no injection vector); tinio-fs receives it as plain injected data (e.g. via `FsOptions`), keeping tinio-fs free of tinio-config/tinio-auth dependencies.
  - **Unmapped owners**: owners with no mapping (default/lazy owner without a configured uid, the anonymous special ID, legacy rows) → no chown; files stay owned by the server-process user, still 0600 (private).
  - **Overwrite/copy**: chown to the **new** owner's uid (overwrite replaces owner; copy's owner = requester). Rename preserves ownership naturally (inode preserved — no chown needed). Multipart: part/temp files live under the already-0700 `.tinio/`; the final chown happens at completion when the object lands.
  - **Implicit prefix dirs**: a PutObject by a non-bucket-owner creates prefix dirs chowned to the **bucket owner** (requires a bucket-owner lookup at dir creation).
  - **Chown failure after rename lands** (e.g. uid vanished from the OS) → fail closed: remove the file, error the request (a wrongly-owned 0600 file must not be left behind).
  - **Rust mechanism**: `std::os::unix::fs::chown`.
- **Canned-ACL expansion and grant-header parsing live in `tinio-auth`** (grilling Q4), which depends on s3s dto types; tinio-core remains s3s-free (wire codec + validation only).
- **PostObject flows through unchanged** (s3s facts, 2026-09-05): a form with `x-amz-signature`/`signature` is policy-verified by s3s and yields the signing user's credentials; a signature-less form is anonymous; `PostObjectInput`'s `acl`/`grant_*` fields reach `put_object` via s3s's default delegation, so write-path ACL parsing covers browser uploads with no extra work. Matrix: PostObject → bucket WRITE.
- **Documented notes** (review A10): `authenticated-read` spans **all configured users** (single-tenant, AWS-consistent); `[users]` secret keys are **cleartext TOML** (existing `[auth]` precedent — config file must be protected by the operator); `x-amz-source-expected-bucket-owner` (the copy-source counterpart) is **not supported** — copy authorization uses the standard source READ + destination WRITE checks; ListObjectsV2 `Owner` is populated unconditionally (no `fetch-owner` gating — minor deviation, AWS only emits it with `FetchOwner: true`); presigned URLs authorize as the **signing principal** (s3s verifies the signature before the access check, so the signer's credentials reach `S3Access`).

## Design

### §1 `tinio-auth` crate and the `acl` feature gate

New workspace member `crates/tinio-auth`; description `"S3 authn/authz engine for tinio"`; dependencies: `tinio-core` (the `Storage` contract, ACL types), `s3s`, `thiserror`; `[lints.rust] unsafe_code = "forbid"` like its siblings. Does **not** depend on tinio-config (the server assembles plain identity data from config and passes it in) or on any redb backend (it reads ACLs through the `Storage` contract).

Modules:

- `identity.rs` — `OwnerId`-based identity model: `User { access_key, canonical_id, display_name }`, `Identity { users: AccessKeyMap, default: Owner }` (access key → user; the root user from `[auth]`+`[owner]` is one entry), the anonymous canonical-ID constant, and the three-way owner resolution rule (write path) from Decisions.
- `auth.rs` — `ConfigAuth` implementing `s3s::auth::S3Auth`: `get_secret_key` → the user's secret, or `Err(s3_error!(InvalidAccessKeyId, "The AWS Access Key Id you provided does not exist in our records."))` (the existing `StaticAuth` phrasing, kept for the FR-008 interop expectation).
- `access.rs` — `AclAccess<S: Storage>` implementing `s3s::access::S3Access`: holds `Arc<S>`, `Arc<Identity>`; performs the authorization pipeline (principal resolution → `expected_bucket_owner` header check → operation mapping → owner bypass → grant evaluation with group rules — the §4 order); fail-closed contract mentioned in Decisions.
- `matrix.rs` — the pure, unit-tested operation→permission mapping (see §4).
- `error.rs` — small mapping from tinio-core contract errors to `s3s::S3Result` (fail-closed `AccessDenied`, pass-through of `NoSuchBucket`/`NoSuchKey`).

`tinio-server/Cargo.toml`: `tinio-auth = { workspace = true, optional = true }`; `[features] acl = ["dep:tinio-auth"]`; `default = ["multipart", "copy", "list-v1", "list-v2", "acl"]`. `#[cfg(feature = "acl")]` gates — the `DataPlane::new_with_acl` constructor + `S3Backend` identity field + the four ACL trait overrides + write-path ACL parsing + `op_list_buckets` filtering + Owner population helpers. With the feature off, `DataPlane::new_with_auth` (StaticAuth) is the only authenticated constructor and the storage rows are written with an **empty (lazy) owner element** and the default private ACL (feature-independent; review B4).

### §2 tinio-core ACL types and codec (`crates/tinio-core/src/acl.rs`)

- `OwnerId(String)` — 64 lowercase hex (validated in the type's constructor; config-provided IDs must match).
- `Permission` enum — `FullControl`/`Read`/`ReadAcp`/`Write`/`WriteAcp`; wire = the AWS strings (`FULL_CONTROL`, `READ`, `READ_ACP`, `WRITE`, `WRITE_ACP`).
- `GroupUri` newtype over the **three documented** constants — `ALL_USERS` (`http://acs.amazonaws.com/groups/global/AllUsers`), `AUTHENTICATED_USERS` (`http://acs.amazonaws.com/groups/global/AuthenticatedUsers`), `LOG_DELIVERY` (`http://acs.amazonaws.com/groups/s3/LogDelivery`). No EC2 constant: AWS documents only these three special-grantee URIs, and no public implementation exists (`groups/s3/EC2` has zero hits across public code, MinIO's Go sources included) — see the `aws-exec-read` ruling in Decisions.
- `Grantee` — `Canonical(OwnerId) | Group(GroupUri)` (email is rejected upstream at the interface).
- `Grant { grantee, permission }`; `AclGrants = Vec<Grant>` with the ≤100 cap, canonical sorting (`(grantee-wire, permission-wire)`), dedupe, and the wire codec above.
- `Acl { owner: Option<OwnerId>, grants: AclGrants }` — the decoded row form; `Acl::default_private(owner)` (owner FULL_CONTROL). The **grant-set wire** is `to_grants_wire` / `from_grants_wire` (owner is its own row element); `from_grants_wire` self-heals to `default_private(None)` on any domain-invalid input.
- Percent codec shared with the tags codec (RFC 3986).

### §3 Storage: shared rows, contract, backends

`tinio-store/src/tables.rs` (the first schema change post shared-store; the schema-assertion test is **extended** here to assert key/value arities as well as table names, making it the byte-format guard the shared-store spec describes):

| Table | Key → Value, after this plan |
|---|---|
| `BUCKETS` | `name → (created_at_nanos, tags_wire, owner_wire, acl_wire)` |
| `OBJECT_META` | `(bucket, key) → (etag, size, mtime, file_identity, tags_wire, checksum_wire, owner_wire, acl_wire)` |
| `UPLOADS` | `(bucket, upload_id) → (key, initiated_at_nanos, tags_wire, owner_wire, acl_wire)` |

- `StoredMeta` gains `owner: Option<OwnerId>` and `acl: Acl` (decode via the codec; invalid `owner_wire` → `None`, invalid `acl_wire` → `default_private(None)` — the established self-heal style). Bucket and upload row decoders gain the same two fields.
- `STATE_VERSION` stays 1; no migration (established ruling).
- tinio-core `Storage` contract:
  - `bucket.rs`: `get_bucket_acl(&self, name) -> Result<Acl>`; `put_bucket_acl(&self, name, grants: &AclGrants) -> Result<()>` (replace-all; the owner element is preserved by the store, never changed by a put); `create_bucket` gains `owner: Option<&OwnerId>` and `acl: &Acl` (None = empty owner wire — the lazy default owner; it has no other params today); the `list_buckets` call gains an `owner: Option<&OwnerId>` filter applied **during the walk, before pagination** (review P2#4: post-walk filtering breaks continuation tokens and would silently drop pages for non-root principals).
  - `object.rs`: `get_object_acl(bucket, key) -> Result<Acl>`; `put_object_acl(bucket, key, grants) -> Result<()>`; `commit_object` / `copy_object` gain `owner: Option<&OwnerId>, acl: &Acl`; `create_multipart_upload` gains both (upload row); complete applies the stored pair — `complete_multipart_upload` takes **no** new params; the fs backend writes the object row from the upload row, applying the stored owner/ACL internally, exactly the tags precedent (read from the upload state the completion consumes, never re-ferried through the interface). `MultipartUpload` (the upload-state struct) and its getter gain `owner: Option<OwnerId>` + `acl: Acl` so the ListParts access check can evaluate the "upload creator or bucket owner" row without a separate fetch.
  - `Info` gains `owner: Option<OwnerId>` and `acl: Acl` so listing/owner-population and the access-check evaluation proceed without a dedicated fetch (the `Info.tags` precedent); `rename_object` preserves both.
- fs/mem backends: the tags-pattern read-modify-write stores (`set_acl`/`clear_acl`-style; preserve the rest of the row) in `tinio-fs/src/{bucket,meta}.rs` and `tinio-mem/src/{bucket,object}.rs`. Overwrite/delete paths handle the new elements like tags (row replace/delete, no extra cleanup).

### §4 Authorization matrix (enforced via `S3Access`)

Principal P (signed user or anonymous special ID under enforced mode; legacy mode has no enforcement). Resource owner O = row owner or lazy default owner.

Owner bypass: P == O ⇒ allowed, regardless of grants (implicit-owner rule). Otherwise the ACL grants are evaluated; group grantees: AllUsers = any P (incl. anonymous); AuthenticatedUsers = any signed P; LogDelivery = never satisfiable (no EC2 group constant exists — see Decisions). Operation→requirement:

| Operation | Requirement (non-owner) |
|---|---|
| ListObjects (v1 — s3s names the op `ListObjects`), ListObjectsV2, ListMultipartUploads | bucket READ |
| ListParts | upload creator or bucket owner (AWS policy-only → tinio's owner-privilege equivalent, the default-A class) |
| PutObject (new key), PostObject, CreateMultipartUpload | bucket WRITE |
| UploadPart, Complete, Abort | upload creator or bucket owner (AWS initiator-only semantics; aligned with ListParts; the bucket-WRITE grantee must not add parts to, complete, or abort another user's upload — completion records the object under the CMU creator's identity, so hijack is also an identity-confusion vector); Complete additionally: when the completed key exists, the B1 existence head applies — P == O(destination object) or P == O(destination bucket) on top of this row's gate |
| UploadPartCopy | source object READ + upload creator or bucket owner (copy-parity on the source, initiator-only on the destination upload) |
| GetObject, HeadObject | object READ |
| CopyObject | source object READ + destination bucket WRITE |
| RenameObject | P == O(source object) or P == O(source bucket) (delete-parity — rename removes the source) + destination bucket WRITE; owner/ACL preserved onto the destination, an overwritten destination's old owner/ACL is replaced; when the destination key exists, the overwrite rule applies to the destination as well (P == O(destination object) or P == O(destination bucket)) |
| DeleteObject / overwrite (PutObject or CopyObject onto an existing key) | P == O(object) or P == O(bucket) (classic ACL: a WRITE grantee may delete/overwrite only its own objects — equivalent under the owner-bypass rule) — for CopyObject, O means the **destination** object/bucket (the source needs only READ, per its own row) — single-key ops evaluated in the access check; the check therefore reads the object row for PutObject (dispatch on key existence); **DeleteObjects** gets the coarse gate (bucket owner or any bucket-ACL grant to P; whole-op 403 otherwise — review B2) at the access check plus a per-key check in the handler (denied keys → per-key `AccessDenied` Error entries in a 200 response) |
| GetBucketAcl / PutBucketAcl | bucket READ_ACP / WRITE_ACP |
| GetObjectAcl / PutObjectAcl | object READ_ACP / WRITE_ACP |
| ListBuckets | any signed P, filtered to P's buckets (in `op_list_buckets`); anonymous 403 (from the access check) |
| CreateBucket | authenticated P only (anonymous 403) |
| HeadBucket | bucket READ |
| GetBucketLocation, bucket tagging (get/put/delete), DeleteBucket | bucket owner (policy-only permissions; owner-only as tinio's equivalent) |
| Object tagging (get/put/delete), GetObjectAttributes | object owner or bucket owner (default A) |
| `expected_bucket_owner` (header, all bucket/object ops) | 403 `AccessDenied` on mismatch when the bucket exists; pass-through when missing |
| Unknown / unmapped ops | owner-only (default B) |

The pipeline order: (1) principal resolution; (2) `expected_bucket_owner` header check; (3) operation→requirement mapping (resolved-but-unmapped ⇒ owner-only; truly unknown paths never reach the check); (4) owner bypass; (5) grant evaluation with group rules; (6) storage errors → fail-closed `AccessDenied`; `NoSuch*` → **three tiers** (review B3): bucket owner → pass-through 404/204; bucket-READ grantee → pass-through 404/204; otherwise 403. S3Access sees `S3Path` (root/bucket/object) and `S3Operation` name — the mapping is a pure function unit-tested as a truth table; the PutObject/PostObject/CopyObject/Complete existence head (review B1) sits between steps (4) and (5). Upload-scoped ops (UploadPart, UploadPartCopy, Complete, Abort, ListParts) resolve the upload row via the `uploadId` query parameter (available through `cx.uri()`) — `S3Path` alone cannot identify an upload (several may be in flight for one key); the upload row's stored owner is the creator the creator-or-bucket-owner rule evaluates against. Note: buckets granted `public-read-write` (AllUsers WRITE) produce anonymous-owned objects (the special anonymous ID); any unsigned request may then delete/overwrite those objects (P == O) — AWS's real public-write semantics, accepted as-is and documented.

### §5 Operation surface (tinio-server)

- **ACL ops** (feature-gated, all under `require_cap(caps.acl)`): `get_bucket_acl`, `put_bucket_acl`, `get_object_acl`, `put_object_acl` — `s3.rs` trait overrides → `op_*` in `buckets.rs`/`objects.rs` → contract → dto out (s3s serializes the XML; no hand-built XML anywhere). Object ops head-check existence → `NoSuchKey` 404 (the tags precedent). PutBucket/PutObject Acl replace grants only; an `AccessControlPolicy` `Owner` that does not match the row owner → 400 `InvalidArgument` (fail-closed). Request-level grant sets are validated strictly (unknown group URI, malformed canonical ID, over the 100-grant cap → 400 `InvalidArgument`) — the codec's self-heal applies to stored-row decode only, never to request input. `MetricS3` wrappers + the metrics-delegation fixture additions (the tagging-ops pattern).
- **Write-path headers**: `op_put_object`, `op_copy_object`, `op_create_bucket`, `op_create_multipart_upload` read the pre-parsed `acl`/`grant_*` input fields → canned expansion or grant parse (canned+grants conflict → 400; email grantee → 400 `InvalidArgument`) → `Acl` for storage. Multipart completes apply the CMU-recorded pair. **PostObject** needs no code — s3s's default delegation carries the form's `acl`/`grant_*` into `put_object`.
- **Put-ACL Content-MD5**: `op_put_bucket_acl`/`op_put_object_acl` validate `Content-MD5` presence + well-formedness (16-byte base64) via one shared helper — aligned to the AWS three-state behavior: missing → 400 `InvalidRequest` (`"Missing required header for this request: Content-MD5"`), malformed (not 16-byte base64) → 400 `InvalidDigest`; digest *equality* against the body is **not verifiable at the op** (s3s's deserializer consumes the body; `S3Request` retains no raw bytes) — recorded deviation (AWS verifies the digest → `BadDigest`, unreachable here). The shared `require_content_md5` helper is **owned by the CORS design** (`2026-09-05-s3-cors-design.md`), which took the AWS-verified three-state behavior; this spec aligns to it at the merge.
- **DeleteObjects per-key authz**: `op_delete_objects` checks each key against the owner/ACL rule (shared helper with the access-check evaluator); the per-key authz check adds one owner/ACL read per key (up to 1000 at max batch) — accepted at dev-local scale, same posture as the no-cache ruling; denied keys are reported as per-key `AccessDenied` Error entries in the 200 response, allowed keys deleted — no partial-failure status changes.
- **Owner surface**: list v1/v2 entry `Owner`, `list_buckets` `Owner`, and the ACL-policy `Owner` — all populated from the row owner (display name resolved via the identity map; unknown → ID-only). `GetObjectOutput`/`HeadObjectOutput` have **no** Owner field (s3s 0.15 dto / AWS), so `Info.owner` serves listings and access evaluation, not head/get responses. `list_buckets` filtering by owner (enforced mode): **filter-then-paginate via a contract-level filter** — the `list_buckets` call takes the owner filter (see §3) so the walk itself yields only the requester's buckets and the continuation-token math applies to the filtered set, not the raw bucket list (review P2#4).
- **Access wiring**: `DataPlane::new_with_acl<S>(storage, caps, Identity)` — `builder.set_auth(ConfigAuth)` + `builder.set_access(AclAccess)`, composed with the existing `MetricS3` wrapper; active only when feature on AND `caps.acl` on. When `caps.acl` is off, `serve.rs` keeps today's `new_with_auth` root-only path (auth required, no ACL evaluation — the "accept-and-drop" off-mode analogue for the whole subsystem). With the `acl` feature/capability off, `x-amz-expected-bucket-owner` is silently ignored (the accept-and-drop analogue) — clients relying on it for delete-protection get silent acceptance. `DataPlane::new` is unchanged (legacy unsigned mode).

### §5a Local filesystem permissions, ownership mapping, and the ACL trust boundary

S3 ACLs are protocol-layer enforcement. The **optional** local-user mapping (see Decisions) adds OS-level per-user isolation on unix when configured and the server is privileged: new object files land `0600` owned by the mapped owner's uid, bucket/prefix dirs `0700` owned by the bucket owner's uid. Local OS users **without** a mapped counterpart bypass nothing they could not already read — mapped users' files are 0600/0700 owned by their uid, so cross-user **local** reads are blocked by the OS (not by tinio). With **no** mapping configured, the hardening story is confidentiality by mode alone: unix object files `0600`, bucket/prefix dirs `0700`, and `.tinio/`/`meta.redb` remain `0700`/`0600` — the asymmetry between ACL data and payload is fully closed by mode even without a privileged run.

Today object files/dirs inherit the process umask (unix default world-readable `0666 & ~umask` files / `0777 & ~umask` dirs), while `.tinio/` and `meta.redb` were hardened (`0700` / `0600`, re-applied at every open) — an asymmetry where the ACL data was protected but the payload was not. This plan **extends the existing hardening to the payload**: on unix, new object files are created `0600` and new bucket/prefix dirs `0700`, applied at creation; with a mapping configured they are additionally `chown`ed to the mapped owner/bucket-owner uid. Pre-existing files are untouched (no retroactive chmod pass). Windows is unchanged — files inherit the creating user's ACLs (existing documented behavior), and `local_uid` is rejected at config parse.

- **Implementation location**: tinio-fs write/bucket paths (`File::create`/`create_dir_all` call sites) plus post-write chown.
- **Spec impact**: `specs/001-s3-local-server` permission-contract notes (`spec.md` / `data-model.md`, currently covering only secret-bearing state) gain the payload-file modes and the ownership-mapping contract.

**Out-of-band edits**: a local content replacement keeps the stored owner/ACL (the `rewrite_preserving` tags/checksum precedent — owner/ACL row elements ride the same path, so the file stays owned by the mapped owner's uid), so the S3 owner is **not** a content-authorship claim; a mapped local user editing their own file changes bytes under the stored ACL — owner ≠ content author, already accepted. Local deletes self-heal rows via the scanner. Documented as accepted.

**403 ambiguity**: fs already reports local `PermissionDenied` as S3 403 `AccessDenied` (`objects.rs:268-280`); after ACLs land, a 403 can mean ACL denial, OS denial, or symlink-policy refusal — the server module docs must call this out and log the source at debug level.

### §6 Configuration (tinio-config)

- `[owner]`: `canonical_id` (default `hex(SHA-256("tinio"))`), `display_name` (default `"tinio"`), `local_uid` (optional, unix-only; the root user's files chown to it).
- `[[users]]`: `access_key` (≥1 char), `secret_key` (non-empty, the existing `validate_auth_secret_key` — a non-empty check only; generated defaults are ≥32 chars), `canonical_id` (optional, default `hex(SHA-256(access_key))`, must be 64 lowercase hex), `display_name` (optional, default `access_key`), `local_uid` (optional, unix-only). Garde checks: unique access keys, unique canonical IDs (including the root `[owner].canonical_id` — a user colliding with the root ID would become root), `InvalidAccessKeyId`-style config errors at startup.
- **OS-mapping validations**: `local_uid` on Windows is rejected at config parse time (fail fast); when **any** `local_uid` is configured (in `[owner]` or `[[users]]`), startup verifies chown privilege (root or CAP_CHOWN) and fails with a config error otherwise (fail-closed; no silent degradation to server-user ownership).
- Root user identity = `[auth]` pair + `[owner]` ID/display (the e2e `minioadmin` pair remains the root in default configs).
- `[s3]` Capabilities gains `acl` (default on); `@minimal-caps` clears it (the tagging precedent).

## Risks

| Risk | Mitigation |
|---|---|
| Lazy default-owner evaluation subtlety (legacy rows) | unit fixtures covering legacy-shape rows; row elements written on first write ever — the lazy path only ever serves pre-existing data |
| Access-check storage reads on every request | accepted at dev-local scale — object ops need **two** row reads (object row + bucket row: `expected_bucket_owner`, bucket-owner rules and the deny-first `NoSuchKey` all need the bucket row), bucket ops one; no cache (non-goal) |
| TOCTOU between check and mutation | accepted dev-local risk (see Decisions) — no cross-call transaction, server per-key locks unreachable from `S3Access`; a concurrent overwrite/ACL change can act on stale authorization; revisit if multi-instance or stronger guarantees |
| Running a network-facing server privileged (root/CAP_CHOWN) | a deliberate security tradeoff, required **only** when a mapping is configured — mitigate by granting `CAP_CHOWN` via `setcap` rather than full root where possible; with no mapping configured the server needs no privilege and the 0600/0700 modes alone apply |
| s3s 0.15 `S3Access` wiring subtleties (auth-set precondition, pre-route ordering) | the plan's first task spikes the wiring in a smoke test before the matrix work |
| e2e legacy scenarios gain `Owner` elements in list/ACL responses (GetObject/HeadObject carry none) | run the existing 12 files; any assertion that pinned absence of Owner is adapted (expected: none) |
| group-URI constants | investigated 2026-09-05: AWS documents exactly three special-grantee URIs; no EC2 URI exists in public code and MinIO does not special-case `aws-exec-read` — resolved by the accepted-but-ignored ruling (see Decisions); no verification task remains |
| feature-off builds must not regress storage contract | contract params are feature-independent (always present); server passes defaults when off — `cargo check` without `acl` in verification |
