# Design: S3 object lifecycle management (FR-042)

**Date**: 2026-10-18
**Status**: draft — awaiting review. Every question this document raised has been ruled on by the operator on 2026-10-18: **Q1 = D** (lifecycle owns all three actions per bucket; the `[s3]` knobs stand down for a bucket carrying the rule — LC21), **pass on by default** with `[lifecycle]` tuning only the pacing and `[s3] lifecycle = true` by default (LC22), **the file stays a seed** (LC13), **the management surface is the stored model as JSON with four CLI verbs** (LC14), and the delivery is **one plan** (§Delivery).

Not touched: the persistence contracts' existing shapes, the version state machine, `Cleanup` and the sweeper **except for the ownership rule §The sweeper's overlap settles**, doctor.
**Spec**: `specs/001-s3-local-server/spec.md` FR-042 — the authoritative requirement; this document is its implementation design and states every decision the requirement leaves open.
**Reference**: AWS S3 object lifecycle management (the subresource's XML, the three local action kinds, the overlap and midnight-UTC rules), MinIO's ILM (expiry driven by the background scanner rather than by request traffic), and RustFS's split of a pure evaluator crate from its operations. ## Background

No lifecycle code exists in the tree: `lifecycle` appears in no crate, no contract and no feature file (the one homonym is the CLI's process lifecycle, `2026-09-20-cli-lifecycle.md`, which this document does not touch). What the feature builds on already exists:

- **The bucket-subresource pattern, end to end.** `cors::Config` is a `tinio-core` model with its own wire (`src/cors.rs`), stored by every backend through `BucketMeta::{set_cors, clear_cors, row}`, served through **`tinio_ops::bucket::BucketOps::{get,put,delete}_bucket_cors`** with each backend a thin forward, mapped to the S3 surface by three handlers in `tinio-server/src/backend/cors.rs`, and gated by `tinio_s3_ops!`'s `#[gated(cors: "cors")]` row plus the `[s3] cors` capability (FR-021's double gate). A lifecycle configuration is the same kind of object and takes the same path, bodies included.
- **The background passes.** The CLI's `ServingBackend` owns one `background` future per backend arm (`crates/tinio-cli/src/commands/start/serving.rs`): fs runs `Scanner` and `Sweeper` on one stop channel, pg runs its own pass. Both launch after readiness, abort quietly on stop, and are skipped entirely in read-only mode — the properties FR-024 requires of background work, already implemented and already tested.
- **The versioning plane.** `VersionOps::list_object_versions` / `delete_object_version`, `version::Entry::is_delete_marker`, and the rows' `became_noncurrent_at` are what the noncurrent and delete-marker rules need.
- **The management plane.** `tinio-api`'s router registers `/status`, `/stop`, `/metrics` and `/openapi.json` before one `route_layer` that guards everything registered; `Context`/`Shared` carries no storage handle (the `MetricsSource` seam is the precedent for one), and the CLI already has a client for it.
- **The framework's dto.** `s3s` 0.17 carries `dto::BucketLifecycleConfiguration` and `PutBucketLifecycleConfigurationInput`, so the XML is the framework's, not ours.

Two facts bound the shape:

- **The bucket row is a fixed 5-tuple** — `(created_at, tags, owner, acl, cors)` — pinned by a type-level test in `crates/tinio-store-redb/src/lib.rs`. A sixth element is a row-format change on every existing database; a **new table** is additive and `FORMAT_VERSION` stays `1` (the 2026-09-02 ruling; the open-time gate reads only the `STATE` row).
- **The purge already has an owner.** Blocks of superseded versions are reclaimed by `Cleanup`; lifecycle removes *keys and versions*, never blocks, and adds no reclamation stage.

## The sweeper's overlap (Q1 — settled: the operator ruled D on 2026-10-18)

Two of the three actions FR-042 names are **already enforced, unconditionally and bucket-blind**, by the fs sweeper and pg's cleanup pass, driven by server-wide `[s3]` keys (`crates/tinio-cli/src/config/s3.rs:36-58`, `crates/tinio-fs/src/sweep.rs:62-98,722-745`, `crates/tinio-pg/src/cleanup.rs`). The fs sweeper enforces both noncurrent retention and the abandoned-upload timeout; pg's cleanup pass enforced only retention at HEAD, so this plan adds its abandoned-upload stage (`PgCleanup::abort_stale_uploads`) as the backend-parity half of the same ownership rule. The knobs are:

| Existing knob | Default | What it already does | The rule it pre-empts |
|---|---|---|---|
| `[s3] multipart_expire_days` | 7 | aborts every incomplete upload idle ≥ N days | `AbortIncompleteMultipartUpload.DaysAfterInitiation` |
| `[s3] noncurrent_keep` | 0 (keep all) | keeps the newest N noncurrent versions per key | `NoncurrentVersionExpiration.NewerNoncurrentVersions` |
| `[s3] noncurrent_expire_days` | 0 (never) | expires noncurrent versions past N days from `became_noncurrent_at` | `NoncurrentVersionExpiration.NoncurrentDays` |

So `DaysAfterInitiation = 30` would be pre-empted at 7 days, and `NewerNoncurrentVersions = 5` by `noncurrent_keep = 2`. A rule whose promise the server quietly beats is worse than no rule.

**The ruling (LC21)**: a bucket's stored configuration governs its own actions. When a bucket's configuration carries one of these actions, **the corresponding `[s3]` knob stops applying to that bucket** and the lifecycle pass owns the action at the rule's own threshold, on the rule's own clock (LC10). The `[s3]` knobs keep their current meaning for every bucket that carries no such rule — an operator who never touches lifecycle sees no behavior change at all. One owner per bucket per action, no two thresholds racing.

## Goal

One lifecycle engine, generic over the persistence contracts, that any backend gets by storing the bucket-rule row: the three locally meaningful action kinds, enforced in the background, managed through the S3 subresource, the management plane and the CLI, seeded from the configuration file, gated at compile time and at runtime, and proven per backend by the shared conformance harness.

## Non-goals

- **Storage-class transitions and tiering.** A local server has no `GLACIER`/`STANDARD_IA`/`INTELLIGENT_TIERING` to move to; accepting the action would promise a migration that cannot happen (LC9).
- **Replication, Object Lock, restore, event notifications.** Each is its own feature with its own requirement.
- **A cursor.** The pass re-lists (LC12); a bounded per-bucket slice is the upgrade path if a real root measures badly.
- **New Prometheus families.** The pass logs one summary per run (LC16).
- **Lifecycle for the block plane.** Blocks are content-addressed and reclaimed by `Cleanup`, not by rules.
- **Any second source of truth for the rules.** The stored per-bucket configuration is authoritative; the file is a seed (LC13) and the S3 subresource, the management plane and the CLI are three views of one stored fact.

## Decisions (proposed 2026-10-18; each tagged with the constraint it serves)

| # | Decision |
|---|---|
| LC1 | **The pass is generic over the contracts, not implemented per backend.** It depends on `tinio_core::storage::Storage` + `VersionOps` only. A backend "plugs in" by storing the rules and already implementing the deletes it is being asked for — no backend gains an expiry loop of its own, which is what makes mem/fs/pg equal rather than sequential work. |
| LC2 | **The pass re-enters the API's own delete semantics deliberately.** Current-version expiration is `Storage::delete_object` — a delete marker in a versioned bucket, an unlink otherwise; noncurrent expiration and expired-delete-marker removal are `VersionOps::delete_object_version` — permanent; abandoned uploads are `Storage::abort_multipart_upload`. That is AWS's own division, so the engine owns no version-aware deletion of its own. **A due key whose current slot is already a delete marker is skipped** (one `current_version` read, paid only for keys already due): adding a second marker every cycle would grow version rows forever, and removing markers is `ExpiredObjectDeleteMarker`'s action, not `Expiration`'s. Confirmed against AWS's own wording — "Amazon S3 doesn't take any action if there are one or more object versions and the delete marker is the current version" — and structurally by MinIO, whose only delete-action site is guarded `is_latest && !delete_marker`. |
| LC3 | **The model lives in `tinio-core`** (`src/lifecycle.rs`: `Config`, `Rule`, `Filter`, `Expiration`, `NoncurrentVersionExpiration`, `AbortIncompleteMultipartUpload`, the JSON row wire, the request-path validation, and the rule matcher) — the `cors.rs` precedent, and the reason `BucketMeta` can name the type without a new crate edge. |
| LC4 | **The pass lives in a new crate, `tinio-lifecycle`**, a peer of `tinio-version`: it depends on `tinio-core` and nothing else in-tree, and exposes `Runner` (options + clock + stop channel) and one `pass` entry point. It is **not** a `Storage` implementation and **not** a `Cleanup` implementation — repairing private state is not what it does. |
| LC5 | **Rules live in a new table, never in the bucket row tuple.** redb gets `bucket_lifecycle` (bucket name → the JSON wire) in the shared `tinio-store-redb` layer, so fs and mem both get it; **pg's table joins `0001_init.sql` — there is no second migration** (operator ruling 2026-10-18: the schema has no deployment to migrate, so the initial file stays its only source of truth, `SCHEMA_VERSION` stays `1`, and a database built from the older `0001` is refused by the recorded-checksum gate (R5) and recreated — the accepted cost of one initial schema instead of a compatibility path nothing needs); the statements are **inline `query!` calls** in the pg store's metadata module (not `sql/meta/lifecycle_*.sql` — the regeneration is the `sqruff`-unlinted consequence the pg design records), and the **table-list pins** (both of them) grow by one name while the **bucket-row 5-tuple pin stays untouched** — the tuple does not change. `FORMAT_VERSION` stays `1`: an older binary reading a newer database ignores a table it does not know, and a stripped build must be able to open a database that carries rules. |
| LC6 | **One seam for the rules, in the metadata contract**: `BucketMeta` gains `lifecycle(&self, bucket) -> Result<Option<Config>>`, `set_lifecycle`, `set_lifecycle_or_create` (the lazy first-sight twin, the `set_tags_or_create`/`set_grants_or_create` precedent: a directory-backed store's pre-existing bucket gains its row and its configuration in one write), `clear_lifecycle(bucket) -> Result<bool>`, and **`lifecycles(&self) -> Result<Vec<(bucket::Name, Config)>>`** — the sweep's read (LC21), one scan of a table that is empty on every root that never configured a rule; a stored name that does not parse is discarded with one warning, the read path's corruption policy. The pass reaches the same scan through the storage contract's `LifecycleRules` (one read per cycle), then intersects it with `list_buckets` so a stale row is unreachable (LC19). **`tinio_ops`' `BucketOps` gains the three S3 bodies** (`get`/`put`/`delete_bucket_lifecycle`) exactly as it owns the CORS bodies, with each backend a thin forward; `put`/`delete` follow the receiver's `BucketRow` policy — a lazy store writes first sight and treats a row-less clear as idempotent, a guaranteed store keeps the `false` → `NoSuchBucket` refusal. `Storage`'s `BucketOps` gains the same three. `tinio-util::testing::assert_bucket_meta_conformance` gains the legs, so fs, mem and pg prove the row through one harness instead of three bespoke tests. |
| LC7 | **The S3 surface is the framework's dto**, added as three rows to `tinio_s3_ops!` (`GetBucketLifecycleConfiguration`, `PutBucketLifecycleConfiguration`, `DeleteBucketLifecycle`) with `#[gated(lifecycle: "lifecycle")]`, so the compile-time `lifecycle` feature and the runtime `[s3] lifecycle` capability are one fact stated once, and a disabled one answers `NotImplemented` (FR-021's pattern). The **wire is `/?lifecycle`** — AWS documents no `?lifecycle-configuration` subresource, and both the deprecated v1 and the v2 API share the one query string, distinguished by request shape; this backend serves the v2 shape (the v1 rule-level `Prefix` is still accepted under LC8) and answers `200` with an empty body on `PUT`, `404 NoSuchLifecycleConfiguration` on a `GET` with nothing stored, and `204` on `DELETE`. |
| LC8 | **Validation is the request path's, never the read path's** (the CORS rule), and it answers **two error classes**: a document that does not match the published schema — two top-level filter predicates, an `And` with fewer than two, both a `Filter` and a legacy `Prefix` — is `MalformedXML`; every semantic violation is `InvalidRequest` (MinIO and RustFS both split these, RustFS through one error-kind constant; AWS's own code for the semantic class is undocumented). The accepted `Filter` is **exactly one** of `Prefix`, `Tag`, `ObjectSizeGreaterThan`, `ObjectSizeLessThan`, `And` — an empty or absent filter means every object — and combining predicates requires `And` (≥ 2 predicates, at most one prefix, unique tag keys); a size *range* therefore needs `And`. The legacy rule-level `Prefix` is accepted only when no `Filter` is present. Limits: 1000 rules; `ID` optional on the wire, ≤ 255 chars, unique within the configuration; **at least one action per rule** (several are legal — AWS's own sample carries two `Transition`s and an `Expiration` in one rule); `Days ≥ 1`; `Date` at midnight UTC — **a date in the past is accepted** and expires on the next pass, which is what lets the end-to-end leg assert a real expiry without a clock override; `NewerNoncurrentVersions ∈ 1..=100`; size predicates non-negative with `ObjectSizeGreaterThan < ObjectSizeLessThan`, bounded by the object ceiling (50 TB), not the retired 5 TiB. Documented refusals: `ExpiredObjectDeleteMarker` never with `Days`/`Date`; `Days` and `Date` never together; neither `ExpiredObjectDeleteMarker` nor `AbortIncompleteMultipartUpload` in a rule whose filter uses tags; `NewerNoncurrentVersions` without a filter is an `InvalidRequest`, as AWS documents. **`PUT` requires a checksum** — `Content-MD5` or any `x-amz-checksum-*`/trailer — because AWS requires one (algorithm-agnostic since 2025) while MinIO's clients still send `Content-MD5`. Missing is `400 InvalidRequest`, a non-16-byte-base64 value is `400 InvalidDigest`; **a mismatch is not verified in this framework version** — s3s consumes the body before the handler and `S3Request` keeps no raw bytes, the same recorded deviation the CORS and ACL surfaces carry, and all three would gain the check together. A tag filter enforces unique keys only: 10 is the object tag cap, not a documented filter cap. Rows self-heal on read — a corrupt wire is `None` **and logs one warning**, never an error and never a rule read as "retain everything" (the RustFS post-mortem: a corrupt retention count once made expiry stop silently). |
| LC9 | **Transitions are refused, not dropped.** A rule carrying `Transition` or `NoncurrentVersionTransition` fails the PUT with `InvalidRequest` naming that the server has no storage tiers. Silently accepting the action would leave an operator believing data is tiered. AWS accepts transitions and MinIO resolves them against its own tiers, so this is a deliberate local-only deviation, recorded as one rather than presented as framework behaviour. |
| LC10 | **Evaluation follows AWS's documented rules and the repo's own clock**: per object, the **earliest applicable expiry across matching `Enabled` rules** wins (AWS: "the shorter expiration policy is honored"), and with only expiration implemented (LC9) that is the whole cross-kind rule — AWS orders across kinds by cost, which LC9 makes moot. `Expiration.Days` counts from the object's last-modified; the expiry instant is `midnight_utc(last_modified + days)`, the rounding AWS and MinIO both document. `NoncurrentVersionExpiration` is evaluated **per key over the whole version chain, newest-first** — a single-object evaluation cannot know how many newer versions survive — with `NoncurrentDays` from the version's `became_noncurrent_at` (the instant its successor was written, AWS's own basis) and `NewerNoncurrentVersions` as a keep count in `1..=100`; **AWS deletes only when both thresholds are exceeded, per rule** — a version is due only if one matching rule's own pair is exceeded, and two rules' thresholds are never combined, because a merged pair (the smallest days with the smallest count) authorizes deletions neither rule permits. The count-only form (keep 3, no days) is MinIO's documented extension and is accepted as such: an absent `NoncurrentDays` means 0, so a version past the count is due at once. `AbortIncompleteMultipartUpload` counts from `initiated_at` — the only documented clock; whether S3 also aborts an upload still receiving parts is undocumented, and this pass follows the clock. A rule's `Filter` still applies: a size predicate matches the bytes already uploaded (one part walk per matching upload), and a tag predicate is refused at validation (LC8). Versioning-suspended buckets follow S3: expiration writes a `null`-version delete marker, and when the current version *is* the `null` version it is permanently deleted — both are the backend's existing `delete_object` semantics, not the engine's. `ExpiredObjectDeleteMarker` removes a marker that is the only version left. A rule's `Filter` matches key prefix, size and tags — the listing already carries `object::Info::tags`, so the object path adds no read. **The version path reads each version's own tags**: `NoncurrentVersionExpiration` is evaluated against that version's tags (a `null` version carries none), so a tag-filtered rule matches per version; the cost is one read per version per pass, bounded by the version walk's page. Refusing the rule at `validate` is rejected — the S3 surface must keep accepting what AWS accepts. R56 first ruled such a rule inert and rejected the per-version read as a cost this design asked to avoid; the read now exists on every layer, so that ruling is retired. |
| LC11 | **The pass is a third background future beside the scanner/sweeper and the pg pass**, launched by the CLI's `ServingBackend` per arm after readiness (SC-005), paced per object, re-run every `cycle`, aborting quietly on the shared stop channel. A read-only run builds no pass at all — the same early return that keeps the scanner and sweeper out of a read-only run. The sweeper carries the complementary rule (LC21): **a bucket whose configuration carries one of its actions is skipped by the sweeper's noncurrent and multipart stages**, per action, from the `lifecycles()` read (LC6). |
| LC12 | **The pass is stateless**: it re-lists each cycle and keeps no cursor, so a restarted run resumes by re-deriving what is due. Accepted: a large bucket's listing is paid every cycle; the upgrade path is a per-bucket slice cursor, recorded here rather than discovered later. |
| LC13 | **The file is a seed, not an authority**: `[[lifecycle.rules]]` entries are applied at the start of a run's **first pass** (never before readiness), upserted by `(bucket, id)` into each named bucket's stored configuration. The seed **requires `id`** — it is the merge key, so an id-less file rule is a configuration error at parse, while an id-less rule arriving through the API is accepted (AWS allows it) and simply never merged with. A rule naming a bucket that does not exist is warned about and skipped (a bucket created later is seeded on the next start); a rule removed from the file is **not** deleted from the bucket, because the file cannot distinguish that from a rule the API added. No file-spelled rule can express a transition. **Ruled 2026-10-18**: the seed stays one-way. Rejected: reconciling the file over the stored configuration (it makes the file a second source of truth and silently overwrites what a runtime client wrote), and deleting a file-removed rule (it needs a remembered "last seeded ids" state, and that state is where the drift lives). |
| LC14 | **The management plane carries the CLI, and never destroys what it cannot serve.** `tinio-api` gains a `LifecycleAdmin` trait (the `MetricsSource` precedent) implemented by the CLI over its storage handle and injected into `Shared`; the three routes (`GET`/`PUT`/`DELETE /buckets/{bucket}/lifecycle`, JSON body = the stored model) are registered **only when the `lifecycle` feature is on and the CLI injects the admin**, before the router's `route_layer` so the existing token rule covers them, and mirrored in `openapi.json`. A build or a run that does not inject the admin answers `404` and can never replace a stored configuration — one mechanism for both causes (LC15's stripped build, LC23's disabled capability). A read-only run refuses `PUT`/`DELETE` through whichever spelling its own backend uses — the store's `AccessDenied`, or the filesystem backend's read-only io error — and the plane answers `403` for both (`lifecycle_failure`), while `GET` is served; the plane is not the S3 operation table, so LC18's "for free" does not cover it. `tinio lifecycle ls <bucket>`, `add <bucket> --id … [--prefix …] [--expire-days …] [--noncurrent-days …] [--abort-days …]`, `rm <bucket>` and `put <bucket> <file>` drive the plane through `tinio-api`'s client; **no S3 client is added to the CLI**, and the CLI never opens a backend store directly (the running server owns it). **Ruled 2026-10-18**: the JSON is the stored model's own shape (snake_case), not AWS's element names; the four verbs are the surface, and `add`'s flags cover the Days-based actions only — a `Date`, an `ExpiredObjectDeleteMarker` or a `NewerNoncurrentVersions` is expressed by `put <file>`, whose body is the whole model. Rejected: a PascalCase body (a third spelling of one fact, and a second schema to maintain in `openapi.json`), an `mc`-style `add <rule.json>` (everyday one-rule edits would need a file), a three-verb surface without `add` (a read-modify-write by hand), and flags for every action (a second, partial editor to keep in step with the model). |
| LC15 | **The feature gate is the facade's**, per PG15/PG16's principle: `lifecycle` on `tinio-server` (three handlers + the capability field), on `tinio-api` (the trait and the routes), on `tinio-cli` (the verbs, the seed, the pass's spawn) and in `tinio`'s `full` set. The model and the row in `tinio-core` are always compiled — a stripped build must read, and never destroy, a database that carries rules. |
| LC16 | **One `tracing` summary per pass** (buckets with rules, objects expired, versions expired, uploads aborted, errors) at info, and nothing per object at info. No new metric families in v1. |
| LC17 | **One wire per surface**: the S3 subresource speaks the framework's XML; the management plane and the CLI speak the stored model as JSON; there is no third spelling and no XML in the configuration file. |
| LC18 | **Read-only mode**: lifecycle `PUT`/`DELETE` on the S3 surface answer `AccessDenied` for free — they are write rows in the operation table — the pass does not run, `GET` answers on both surfaces, and the plane's writes answer `403` through LC14's mapping (either backend's read-only spelling). |
| LC19 | **Rules die with the bucket, and never outlive it into a new one**: **whichever path a backend's bucket deletion already takes clears the row** — **no production delete path calls `BucketMeta::remove`** — each backend's own teardown is the one to extend: fs's `remove_bucket_state` (where `bucket_versioning` is drained today), mem's `MemHooks::teardown` (inside its single write transaction — the 2026-10-08 ruling that elides `remove_if_empty` stands, so the drain joins that transaction and never opens a second). **pg's table carries `REFERENCES buckets(name) ON DELETE CASCADE`**, so the row dies in the statement that removes the bucket row and no CTE delete exists; `create`/`record_full` need no drain there either, because the cascade has already removed any row a vanished bucket could have left. fs and mem have no such FK, so their **`create`/`record_full` still clear the row** — a brand-new bucket must not silently expire objects. `record_if_absent` needs no such clear: it only fires for a bucket that exists without a row, and no lifecycle row can outlive its bucket's delete. A row left behind by a bucket that vanished out of band is unreachable (the pass reads rules only for buckets `list_buckets` returned); fs/mem reclaim it through `Cleanup`'s stale-bucket stage, while pg's FK makes the state impossible. |
| LC20 | **FR-007's "no data commands" stands**, and this is its one exception: `tinio lifecycle` configures a server-side policy through the management plane; it does not create, read, write or delete buckets or objects. The CLI contract's `lifecycle` section states the exception and the verbs, `contracts/s3-surface.md` states the subresource, `contracts/config.md` states `[lifecycle]` and `[[lifecycle.rules]]`. |
| LC21 | **Operator ruling 2026-10-18 (Q1-D): one owner per bucket per action.** A bucket whose stored configuration carries `NoncurrentVersionExpiration` (or `AbortIncompleteMultipartUpload`) is governed by its rule for that action, and the corresponding `[s3]` knob — `noncurrent_keep` / `noncurrent_expire_days`, `multipart_expire_days` — does not apply to that bucket. The knobs keep their current, bucket-blind meaning for every bucket without such a rule, so an operator who never configures lifecycle observes no change — **the pg abandoned-upload stage runs only when `[s3] multipart_expire_days` was written**, so a default pg configuration keeps the behavior it had before this surface existed. **This ownership is the pass's**: a run that builds no pass (LC23, or a stripped build) governs nothing, so the knobs do their normal work on every bucket, stored rules or not. The alternative settlements were rejected on the record: refusing the two actions in v1 (a feature that does not do what its name says) and letting the server's knobs remain a floor (a rule's stated threshold silently beaten by the server's own). |
| LC22 | **Operator ruling 2026-10-18: the pass is on, the section only tunes it.** A build carrying the `lifecycle` feature runs the pass whenever it serves; `[s3] lifecycle` defaults to `true`. The `[lifecycle]` section is **optional pacing, not a gate**: `delay` (per-object pacing) and `cycle` (full-pass cadence, the sweeper's own interval), each overridable by the section, and its absence means the defaults, never "off" — the values themselves are owned by `contracts/config.md` §`[lifecycle]`. Rejected: presence-gating the section like `[scanner]` — a root with rules but no `[lifecycle]` section would read `?lifecycle` happily and expire nothing, the silent failure this feature exists to remove. Turning the capability off is LC23's switch, not the section's. |
| LC23 | **Operator ruling 2026-10-18: the capability is a whole-feature switch.** `[s3] lifecycle = false` turns off the three S3 operations (`NotImplemented`), **the pass, and the seed** — the CLI injects no `LifecycleAdmin`, so the plane's three routes answer `404` exactly as a stripped build's do (LC14), and the CLI's verbs say the server has lifecycle disabled. Stored configurations are **left untouched**, so restoring the capability resumes enforcement with the rules that were already there — and while it is off no bucket is governed (LC21), so the `[s3]` retention knobs keep working on every bucket: the switch stops the rules, never the server's retention. Rejected: leaving the pass running while the API is off (a disabled capability silently deleting data is the surprise this ruling removes), and leaving the plane writable (rules that can be edited but never run, with nothing saying so). |

## Design

### The model and the matcher (`tinio-core/src/lifecycle.rs`)

`Config { rules: Vec<Rule> }`; a `Rule` carries `id: Option<String>`, `status: Status`, `filter: Filter`, and its actions (`expiration`, `noncurrent_version_expiration`, `abort_incomplete_multipart_upload`). The row wire is JSON, versioned by the crate (`to_wire`/`from_wire`), and decoding never errors — an unreadable wire is `None`.

The matcher is a pure function over the facts a listing already carries (no extra reads):

```rust
pub fn expiry_for(&self, facts: &Facts<'_>, now: SystemTime) -> Option<SystemTime>;
```

`Facts` = key, size, last_modified, tags (`&Tags`). Day arithmetic lives in one place: `midnight_utc(anchor + days)`.

### The pass (`tinio-lifecycle`)

```rust
pub struct Runner<S: Storage> { /* storage, clock, stop, options */ }
pub async fn pass<S: Storage>(storage: &S, cfg: &Config, clock: &dyn Clock) -> Summary;
```

`pass` walks buckets (`list_buckets`), reads each bucket's configuration (one `BucketMeta` call), and skips those without one. Per bucket:

1. `list_objects` (paginated, no prefix) → for each entry, compute the matching rules' earliest expiry; when due, skip if the current slot is a delete marker (LC2), else `delete_object`.
2. If any rule carries `NoncurrentVersionExpiration` → `list_object_versions` and `delete_object_version` for the versions past `NoncurrentDays` or beyond `NewerNoncurrentVersions`, and for an only-version delete marker under `ExpiredObjectDeleteMarker`.
3. If any rule carries `AbortIncompleteMultipartUpload` → `list_multipart_uploads` and `abort_multipart_upload` for uploads older than `DaysAfterInitiation`.

Every action is idempotent: a key that vanished between listing and delete answers `NoSuchKey`, which the pass counts and swallows. Pacing sleeps between items and the loop re-checks the stop channel between items.

### Storage of the rules

| Layer | Where |
|---|---|
| Contract | `BucketMeta::{lifecycle, set_lifecycle, set_lifecycle_or_create, clear_lifecycle}` (LC6), `tinio-core/src/meta/bucket.rs` |
| Bodies | `tinio-ops/src/bucket.rs` (the CORS precedent), each backend a thin forward |

### The S3 surface (`tinio-server/src/backend/lifecycle.rs`)

Three handlers over `BucketOps`, shaped exactly like `cors.rs`: map the dto to the model, validate (LC8), map back on `GET`. The wire is `/?lifecycle` (LC7). `PUT` without a body, or without the checksum LC8 requires, is refused (`MalformedXML` / `400` respectively); a document whose shape violates the schema is `MalformedXML`, a semantic violation is `InvalidRequest` naming the offending rule's id; a body carrying transitions is `InvalidRequest` naming the missing tiers (LC9). A bucket with no configuration answers `NoSuchLifecycleConfiguration` on `GET`, as AWS does.

### The management plane and the CLI

`tinio-api`'s `LifecycleAdmin` trait (LC14) with three methods over a bucket name and the model; the CLI's implementation reads and writes through `Storage`'s `BucketOps` and maps a read-only refusal — `AccessDenied` or a filesystem read-only io error — to the plane's `403`. Routes are registered only in a `lifecycle` build, before the `route_layer`, and documented in `openapi.json`. `tinio-cli/src/commands/lifecycle/` holds the verbs (LC14).

### The declarative seed

`[lifecycle]` (pacing only: `delay` default 10 s, `cycle` default 1 h — LC22) and `[[lifecycle.rules]]` (the seed) live in the configuration root; the CLI owns both the section and the pass's spawn (the config-ownership rule, 2026-10-17). The seed runs at the start of the first pass: read, upsert by `(bucket, id)`, write back; a bucket that cannot be written is a warning in the pass summary, never a startup failure.

### Read-only and the gates

Read-only runs: no pass, `GET` on both surfaces, writes refused (S3 through the operation table, the plane through LC14's mapping). Feature/capability off: the three operations are absent from the table (compile) or answer `NotImplemented` (runtime); the pass is not spawned; **the plane's routes do not exist**, so nothing can replace a stored configuration; rules still decode on read so a stripped build never destroys them.

## Review Focus

Failure modes the requirement implies and no single task's happy-path test would catch; each gets its test in the owning task.

### Data safety

- **A versioned bucket loses data.** Current-version expiration adds a marker, never deletes; only `NoncurrentVersionExpiration` removes.
- **Markers breed.** A marked key gains no second marker per cycle (LC2); `ExpiredObjectDeleteMarker` removes only a last version.
- **`NewerNoncurrentVersions` deletes too much.** Keep 3 of 5 noncurrent versions: exactly the two oldest go, never the current.
- **Overlapping rules expire early or late.** Two matching rules act on the earliest `Date`; a later rule cannot shorten an existing life.

### Rule semantics

- **A tag-filtered rule acts on untagged objects.** A required tag never matches an object without it (listing tags, no default).
- **A keep count deletes the wrong side.** Count-only spares the count; two thresholds need both; per-object evaluation is this bug.
- **A new bucket inherits stale rules.** Create-then-expire is unreachable (LC19): create and remove clear the row.
- **The seed becomes an authority.** A file-removed rule stays stored; a rule for a missing bucket warns, never fails startup.

### Gates and wiring

- **A gate is bypassed.** Capability off leaves no pass and no plane write (LC14/LC15); read-only refuses writes on both surfaces.
- **The sweeper and the rule both act, or neither does** (LC21): the action's owner is the pass at the rule's threshold.
- **A filter is refused for the schema's reason.** Two top-level predicates are `MalformedXML`, the `And` form accepted; no class flip.

## Accepted limits

- **Stateless re-list every cycle** (LC12): a root with a very large ruled bucket pays a full listing per cycle.
- **No tiering** (LC9): a client whose workflow is transition-based gets a refusal, not an emulation.
- **`Date` in the past expires on the next pass**, not at the request; AWS's own eventual consistency is looser than that.
- **An incomplete upload still receiving parts is aborted at the rule's clock**: initiation is the only clock AWS documents, and whether the service spares an in-flight upload is undocumented. MinIO does not implement this action at all — it sweeps every idle upload server-wide — so LC21 has no MinIO precedent either.
- **One writable instance per database** (PG12; unchanged) — the pass assumes it, like every other writer.

## Prior art (what the research changed)

The research note beside this file owns the citations: `lifecycle-prior-art-research.md` — §1–§9 AWS and MinIO (MinIO pinned `7aac2a2c…`), §10 RustFS (pinned `3b0ee834…`). It corrected LC8's filter grammar, size bound and action count, added the checksum requirement and the documented refusals, and fixed LC10's `NewerNoncurrentVersions` semantics — those edits are in the decisions above, not here.

- **Adopted from RustFS**: the pure model/evaluator crate with no storage dependency (LC3/LC4 — it survives contact with a real implementation, and the adapter is one function); per-key evaluation over the whole version chain (LC10 — "a single-object lookup cannot prove how many newer versions survive"); one error-kind constant separating schema shape from semantics (LC8); fail-closed with a warning on a corrupt persisted rule (LC8, from a post-mortem where a corrupt count silently stopped version expiry); and the argument for LC12 — RustFS journals only side effects that cannot be re-derived (remote tier deletes) and re-derives expiry from the listing after a restart.
- **Not adopted (over-engineering at this scope)**: RustFS's twelve-namespace durable journal with record digests and identity proofs, fleet proofs, leader locks, manual transition-job leases and a sharded, live-resizable expiry worker pool — all of it serves remote tiers and multi-node data movement this server does not have; and its tunable "day length" env var, which changes when a day ends in production. Tests inject a clock (LC4) instead.
- **Rejected on evidence**: RustFS's noncurrent clock (the successor's mod time, so overwriting the current version restarts every older version's clock) and its action-priority-first overlap; AWS documents the successor-creation basis and earliest-date, and LC10 follows it. MinIO's own architecture — scanner-driven, stateless re-list, midnight rounding — is the one this design already chose.
- **Not copied from MinIO**: it does not implement `AbortIncompleteMultipartUpload` (the element is silently dropped and a server-wide idle-upload sweep does the work), so LC21's per-bucket ownership of that action is AWS behaviour this server keeps, not MinIO parity.
