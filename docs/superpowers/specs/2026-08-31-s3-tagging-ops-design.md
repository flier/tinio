# Design: S3 object & bucket tagging, RenameObject, GetObjectAttributes

**Date**: 2026-08-31
**Status**: approved — grilled and user-confirmed 2026-08-31 (Q1–Q12)
**Scope**: tinio workspace, end-to-end — object tagging (tinio-core storage contract, fs/mem backends, all S3 write paths, tagging-directive, tagging-count) plus bucket tagging, behind a `tagging` capability toggle; RenameObject with source + destination conditionals; GetObjectAttributes with multipart part retention. Companion spec: `2026-08-31-s3-conditionals-design.md` (the conditional-headers machinery RenameObject and the CMU/Abort condition evaluation reuse). Not touched: PostObject (delegation covers its tagging), RestoreObject / SelectObjectContent / WriteGetObjectResponse (still NotImplemented), tinio-config schema beyond the toggle.

## Goal

1. **Object tagging is real.** Tags are stored with the object (fs + mem backends), served by GetObjectTagging, replaced by PutObjectTagging, removed by DeleteObjectTagging, carried by Put/Copy/Multipart writes, copied/overridden per `x-amz-tagging-directive`, and counted on Get/Head via `x-amz-tagging-count` — behind a `tagging` capability toggle consistent with multipart/copy/checksum.
2. **Bucket tagging is real.** Put/Get/DeleteBucketTagging behind the same toggle.
3. **The remaining dto surface closes.** RenameObject (source + destination conditionals under the `copy` gate); GetObjectAttributes returns ETag / size / storage class / the **recorded** checksum (see Decisions) and — for multipart objects — the persisted part list.
4. **Behavior is locked by tests.** Tags contract in the `assert_conformance` suite, HTTP behavior in the cucumber migration's `tagging.feature` / `objects.feature`, evaluator details in unit tests.

## Non-goals

- **No PostObject work.** s3s's default `post_object` delegates to `put_object` (s3_trait.rs:4654-4659), carrying `if_match`/`if_none_match`/`tagging` through the conversion (generated.rs:41967-41982) — tagging flows automatically once `op_put_object` parses `x-amz-tagging`. Nothing to build for PostObject itself.
- **No RestoreObject / SelectObjectContent / WriteGetObjectResponse.** RestoreObject is Glacier-tier restore semantics tinio has no tiering for (`S3Location.tagging` stays moot); SelectObjectContent is a SQL-engine-scale feature; WriteGetObjectResponse is a data-plane write-back op with no meaning for tinio. All stay `NotImplemented`.
- **No string interning for tag keys.** `Tags` is a plain `BTreeMap<String, String>` — interning was proposed during brainstorming and explicitly dropped by the user; the fs backend persists tags as text, and interning would add a process-local table with no measurable win at object scale.
- **No conditional-headers work** — the companion spec `2026-08-31-s3-conditionals-design.md`; RenameObject consumes its machinery.
- **No removal of existing Rust tests.** They stay until the cucumber migration (separate plan) reaches parity; new HTTP-level coverage lands as cucumber features from the start.

## Decisions (locked in brainstorming + grilling, 2026-08-31)

- **Tagging depth**: end-to-end (storage contract → operations → write paths) + `x-amz-tagging-directive` COPY/REPLACE + `x-amz-tagging-count` + bucket tagging (added 2026-08-31 second pass).
- **Tagging toggle**: new `tagging` capability (consistent with `copy_object`/`checksum`); toggle off ⇒ the **six** tagging operations (three object + three bucket) answer `NotImplemented` and the tagging write headers stay accept-and-drop (the established off-mode, see `multipart.rs:221`). This resolves the dangling "spec §Tagging" reference in `tinio-e2e/tests/steps/mod.rs:57`.
- **Toggle defaults on**: `tagging` is on by default, unlike `checksum` (which defaults off — the lone exception; the five op-group toggles default on); `@minimal-caps` clears tagging too (six caps); e2e gains a `@tagging-off` tag.
- **No version compatibility (user-confirmed, 2026-08-31; amended 2026-09-02)**: the project is in development with no released data — no migration paths, no compat shims, no schema-version tolerance anywhere. Concretely: tags + checksum extend the redb tuples (object row gains 5th/6th elements, upload row a 3rd, bucket row a tags element) encoded as canonical wire strings; a new `OBJECT_PARTS` side table retains completed-multipart part lists. **`STATE_VERSION` reverts to 1** (user ruling 2026-09-02: the multipart-era 1→2 bump is undone — the constant returns to the value the schema docs (meta-redb-spec) record; additive schema changes — the multipart checksum tables, this plan's tagging rows — carry no version bump). The existing open-time gate is untouched: any stored version other than 1 is refused; a stale same-version DB from a different format may fail at row decode — dev-local disposable state, delete by hand.
- **Info.tags always populated**: `get_object_info`/head/listing carry `Info.tags`; GetObjectTagging and `x-amz-tagging-count` read the same field — no dedicated tag fetch on the read paths.
- **Tagging ops take no per-key lock**: `put_object_tags`/`delete_object_tags` do not join `conditional_put_locks` — AWS gives no atomicity guarantee between tag writes and object writes; last-writer-wins is accepted.
- **RenameObject**: gated under the `copy` capability (object-movement group); dual per-key critical sections (acquired in sorted order, deadlock-free) around head-both → evaluate → storage rename. An existing destination with no destination conditions is **overwritten** (AWS implies it: overwriting is prevented only by adding `If-None-Match`); source == destination → 412 `PreconditionFailed` (the only AWS statement, in the console docs). Source conditions evaluate against the source object — missing source → 404 `NoSuchKey` (AWS does not document the code; tinio's choice). Precedence (user ruling 2026-09-03): the missing check precedes the degenerate-key 412 — renaming an absent key onto itself answers `NoSuchKey`. Destination conditions go through the shared `check_destination_conditions` policy — AWS-verified: `If-None-Match: *` with an existing destination → 412; with a missing destination the rename **succeeds** (200); the shared policy matches (missing + If-None-Match → proceed). s3s quirks: `RenameSourceIfMatch`/`RenameSourceIfNoneMatch` alias `String` (generated.rs:20463/20467), parsed with ETag semantics; destination conditions are plain `If-Match`/`If-None-Match` headers on the wire, modeled as `destination_if_*` dto fields.
- **GetObjectAttributes + checksum recording**: ETag / ObjectSize / StorageClass / Checksum / ObjectParts per the requested `object_attributes` list, honoring `max_parts` (default **1000** — AWS documents no GetObjectAttributes default; ListParts' universal 1000 applies) with `is_truncated` / `next_part_number_marker` / `part_number_marker` / `total_parts_count`. The object's checksum is **recorded at write time** (a new `OBJECT_META` tuple element — no bump for the tagging rows; `STATE_VERSION` is back at 1, user ruling 2026-09-02): plain PUT with `x-amz-checksum-*` validates via the tee (under the `checksum` toggle — off keeps today's accept-and-drop) and stores the validated value; multipart completion **receives the composite from the interface** — computed by the **existing `compose_composite`** (checksum-of-checksums: the hasher over the concatenated raw part digests, uniformly for every algorithm; the crc-combine idea is dropped, see Design) and passed through the contract parameter (grilling Q1b); copy carries the source's recorded checksum (the bytes are identical; AWS documents the automatic carry); rename preserves it. `Info` gains the recorded checksum **with its kind** (`FULL_OBJECT` / `COMPOSITE`, recorded at write time; populated on read, like tags); GET/HEAD echo it as the corresponding `x-amz-checksum-*` header plus `x-amz-checksum-type` (unconditional — no `checksum-mode` gating). Multipart completion also persists the part list to `OBJECT_PARTS` (rows: part number, size, algorithm, checksum value); non-multipart objects omit `ObjectParts` (matches AWS).
- **s3s surface sweep (2026-08-31)**: the full dto interface was inventoried — the only tagging surfaces beyond this plan's scope are in ops that stay `NotImplemented` (RestoreObject, SelectObjectContent, WriteGetObjectResponse) or the delegation-covered PostObject. `GetObjectOutput.tag_count` exists (generated.rs:10404, serialized as `x-amz-tagging-count`); `HeadObjectOutput` lacks it — the header is hand-set via `S3Response.headers` (protocol.rs:144). Completed-object checksums are not persisted today (the checksum tables are in-flight-upload-only) — this plan records them at write time (see above). Duplicate tag keys — in the XML `TagSet` or the header — answer `InvalidTag` (400): AWS documents no exact code, so this is tinio's choice.
- **Grilling resolutions (2026-08-31)**: destination-exists → overwrite; src == dst → 412; source-missing 404 (AWS silent); missing destination + `If-None-Match` → success; `OBJECT_PARTS` rows carry part number / size / algorithm / checksum and are cleaned on overwrite and delete, migrated on rename, never inherited by copy; `max_parts` default 1000 with truncation fields; composite checksums = checksum-of-checksums via the existing `compose_composite` (crc-combine dropped; CRC64NVME keeps the uniform path — AWS makes it always full-object, recorded as a known deviation); recorded checksums echo on GET/HEAD unconditionally; duplicate tag keys → `InvalidTag`; no explicit `x-amz-tagging` size cap (the per-tag limits — key ≤128, value ≤256 — plus the 8 KB transport header limit bound it; AWS's 2 KB figure is undocumented); tags share one RFC 3986 codec on disk and in the header (`+` literal, `%20` = space); `tagging` defaults **on** (the "(like `checksum`)" aside was wrong — `checksum` defaults off); `@minimal-caps` clears tagging.
- **New spec IDs**: `specs/001-s3-local-server` gains new FR/SC IDs for the tagging contract (object + bucket), RenameObject, and GetObjectAttributes.

## Design — object tagging

### Core type (`tinio-core/src/object.rs`)

- `Tags` newtype over `BTreeMap<String, String>` (sorted output, deterministic tests). `Info` gains `tags: Tags` (default empty).
- **Validation on the core type** (shared by the interface and the harness): key 1..=128, value 0..=256 (empty values allowed), lengths counted in UTF-16 units (AWS counts UTF-16 positions — `API_control_Tag.html`, `userguide/object-tagging.html`); charset — Unicode letters, numbers, and spaces plus `+ - = . _ : / @` (the S3 Control regex `[\p{L}\p{Z}\p{N}_.:/=+\-@]`, a superset of the EC2 cross-service ASCII restriction); duplicate keys rejected → `TagError`. The **count limit is per surface**: ≤10 for object tags, ≤50 for bucket tags (AWS-verified: `CostAllocTagging.html` "as many as 50 tags"). The `x-amz-tagging` header (URL-encoded `k=v&k2=v2`, percent-decoded) parses into `Tags` through the same validator; malformed input → `InvalidTag` (400) at the interface.
- **Wire format** — one codec for disk and header: tags serialize as sorted-by-key `k=v&k2=v2` with RFC 3986 percent-encoding; the header decodes RFC 3986-strict (`+` stays literal, `%20` is space — AWS documents nothing, this matches SDK encoding); decode failures → `InvalidTag` (400). No explicit size cap on `x-amz-tagging` (see Decisions).

### Storage contract (`tinio-core/src/storage/object.rs`, `bucket.rs`, `multipart.rs`)

- New methods: `get_object_tags` / `put_object_tags` (replace-all) / `delete_object_tags`; bucket counterparts `get_bucket_tags` / `put_bucket_tags` / `delete_bucket_tags`. Get/Put on a missing object → `NoSuchKey` (bucket: `NoSuchBucket`); delete on a missing object/bucket succeeds (matches S3).
- **Write-path signatures gain `tags`**: `commit_object(..., tags)` and `copy_object(..., tags)` carry tags atomically with the write — no post-commit tag window. `create_multipart_upload(..., tags)` stores them in the upload state; `CompleteMultipartUpload` passes them to `commit_object`.
- **`rename_object(bucket, src, dst)`** — the atomic move primitive (fs: single metadata-DB transaction re-pointing the record; mem: same).
- **`list_object_parts(bucket, key)`** — the completed object's retained part list (empty for non-multipart objects), feeding GetObjectAttributes.
- **`stage_body` gains the tee slot** — `stage_body(bucket, key, body, checksum: Option<Arc<checksum::PartChecksum>>)` (the `upload_part` pattern): plain PUTs validate client `x-amz-checksum-*` values while staging, under the `checksum` toggle.
- **fs backend**: rows extended per the Decisions section (object row gains the tags **and** checksum elements); **mem backend**: same tuple extensions over the in-memory redb (fresh per boot, no version gate). Both backends trust validated `Tags` only — the interface validates before the contract is called. Tags persist as the canonical wire string (sorted, RFC 3986); the checksum element is `<algorithm wire>:<base64 value>:<kind>` (`FULL_OBJECT` for plain PUTs and copies, `COMPOSITE` for multipart completions; the kind is recorded at write time so read paths never derive it; empty = none).

### S3 interface (`tinio-server/src/backend/objects.rs`, `multipart.rs`, `buckets.rs`, `s3.rs`, `metrics.rs`)

- **Toggle**: `Capabilities` gains `tagging` (tinio-config schema, default on); the six tagging operations gate on `require_cap(tagging)` → `NotImplemented` when off. Write headers (`x-amz-tagging`, `x-amz-tagging-directive`) are accept-and-drop when off.
- **GetObjectTagging** (`objects.rs:286`): keep the existence head (404 `NoSuchKey`), return the real `TagSet` instead of the fabricated empty one.
- **PutObjectTagging**: validate the dto-parsed `TagSet` (duplicate keys → `InvalidTag` 400), `put_object_tags` (replace-all). **DeleteObjectTagging**: `delete_object_tags`; missing object → 204. Both take no per-key lock.
- **PutObject**: parse `x-amz-tagging` → `commit_object(tags)`. (`x-amz-tagging-directive` is CopyObject-only — ignored on PUT if the dto surfaces it.)
- **CopyObject**: `x-amz-tagging-directive` — COPY (default) carries source tags via `copy_object(tags)`; REPLACE uses the `x-amz-tagging` header result (empty when absent).
- **CreateMultipartUpload / CompleteMultipartUpload**: tags stored in upload state, applied at completion.
- **x-amz-tagging-count**: GET sets the dto field `GetObjectOutput.tag_count`; HEAD has no such field — the header is hand-set via `S3Response.headers`. Omitted when the object has no tags, matching AWS.
- **New ops wiring**: `put_object_tagging` / `delete_object_tagging` gain `S3` trait overrides in `backend/s3.rs`, `op_*` fns, and `MetricS3` wrappers (the `get_object_tagging` pattern at `metrics.rs:1013`); the metrics delegation test fixture adds the new inputs. `rename_object` / `get_object_attributes` get the same override + `MetricS3` wrapper + fixture treatment.

## Design — bucket tagging

- **Storage**: bucket records gain a tags element (canonical wire string, empty = none) — same tuple-extension mechanism as object records; no version bump for the tagging rows (`STATE_VERSION` back at 1 — user ruling 2026-09-02).
- **Interface**: `PutBucketTagging` (validate the dto `Tagging` — the 50-tag bucket cap → replace-all), `GetBucketTagging` (real `TagSet`), `DeleteBucketTagging` — all three gate on the `tagging` toggle; `s3.rs` overrides + `MetricS3` wrappers.

## Design — RenameObject

- **Semantics**: atomically move source key → destination key. An existing destination with no destination conditions is **overwritten** (the AWS API implies it: "To prevent overwriting an object, you can use the `If-None-Match` conditional header"). `source_if_*` (match / none-match / modified-since / unmodified-since) evaluate against the source object — missing source → 404 `NoSuchKey` (AWS does not document the code; tinio's choice). Source == destination → 412 `PreconditionFailed` (the only AWS statement, in the console docs). `destination_if_*` evaluate against the destination via the shared `check_destination_conditions` policy — AWS-verified: `If-None-Match: *` with an existing destination → 412; with a missing destination the rename **succeeds** (200); the shared policy matches (missing + If-None-Match → proceed). On the wire, destination conditions are plain `If-Match`/`If-None-Match` headers (no `x-amz-rename-object-destination-*`); s3s models them as `destination_if_*` fields.
- **Atomicity**: both keys' per-key critical sections acquired in **sorted order** (deadlock-free) → head both → evaluate → call the storage primitive.
- **In-flight multipart uploads**: an upload created for the source key keeps its recorded key — completing it after a rename recreates the source key. Accepted as a last-writer-wins race (dev-local); no extra coordination.
- **Toggle**: gated under the `copy` capability.

## Design — GetObjectAttributes

- **Read op** (no conditions, no toggle): returns the requested subset of ETag / ObjectSize / StorageClass / Checksum / ObjectParts per the `object_attributes` list. StorageClass is always STANDARD (tinio has no tiers). The Checksum attribute echoes the **recorded** object checksum (`Info.checksum`, with the recorded kind as `checksum_type`) — no computation on the read path.
- **Part pagination**: honor `max_parts` (default **1000** — AWS documents no GetObjectAttributes default; ListParts' universal 1000 applies) and `part_number_marker` (listing starts after the marker); set `is_truncated`, `next_part_number_marker`, and `total_parts_count`. With `MAX_PART` = 10,000, truncation is a real path.
- **Recording at write time** (all under the existing `checksum` toggle; off keeps today's accept-and-drop):
  - `PutObject` with `x-amz-checksum-*`: `stage_body`'s tee slot computes the digest while staging and validates at stream end (mismatch → the same BadDigest path as multipart); the validated value is stored in the object record.
  - `CompleteMultipartUpload`: the interface computes the composite of the retained part checksums via the **existing `compose_composite`** — checksum-of-checksums (the hasher over the concatenated raw part digests), uniformly for every algorithm — and passes it to storage through the `complete_multipart_upload` contract parameter (grilling Q1b; it is the value the complete path already derives for the response echo). The crc-combine idea is dropped: AWS documents only the checksum-of-checksums form (the SHA-256 Java example) and states the composite "may not be a direct checksum value of the full object", which crc-combine — always the full-object value — would violate. CRC64NVME keeps the uniform path; AWS makes it always full-object — recorded as a known deviation.
  - `CopyObject`: carries the source's recorded checksum (the bytes are identical; AWS documents the automatic carry). A client-specified `x-amz-checksum-algorithm` on the copy is accept-and-drop — the copy always carries the source's algorithm (known deviation: AWS recomputes the requested algorithm). `RenameObject`: the record move preserves it.
- **Echo on reads**: GET and HEAD set the corresponding `x-amz-checksum-*` response header plus `x-amz-checksum-type` whenever `Info.checksum` is recorded (AWS behavior; present only when the checksum was uploaded with the object). Unconditional — no `x-amz-checksum-mode` gating.
- **Parts retention**: multipart completion currently drains `PARTS`; completion now persists the list to the new `OBJECT_PARTS` side table in the same transaction — rows carry `(part_number, size, algorithm, checksum value)`, serving `ObjectPart.Size` and the per-part checksum fields. Lifecycle: overwrite and delete (including multi-delete `DeleteObjects`) remove the key's rows in the same transaction; rename migrates them with the record; `CopyObject` does not inherit (the copy is single-part). Non-multipart objects omit `ObjectParts`.

## Testing

- **Unit** (`tags.rs` module, `checksum.rs`): `Tags` parse/validate (key 1..=128 / value 0..=256 incl. empty, per-surface count caps 10/50, Unicode charset, duplicates, malformed header, Unicode wire round-trip), `compose_composite` (checksum-of-checksums across algorithms; mixed-algorithm rejection lives upstream at complete time, `multipart.rs:634-642`).
- **Conformance** (`tinio-util assert_conformance`): tags round-trip, replace-all, delete, copy carries tags, multipart completion carries tags, tags present in head/get metadata; bucket tags round-trip (incl. the 50-tag cap); rename (with and without conditions, destination overwrite, same-key 412); completed-object part listing (incl. truncation and per-part fields); GET/HEAD checksum echo; duplicate tag keys → `InvalidTag`.
- **Cucumber** (in the existing `crates/tinio-e2e`): `tagging.feature` grows the six operations, `x-amz-tagging` on put/copy/multipart, directive COPY/REPLACE, `x-amz-tagging-count`, toggle-off `NotImplemented` (via the new `@tagging-off` tag); `objects.feature` grows GetObjectAttributes (incl. pagination); `conditions.feature` grows RenameObject scenarios (incl. overwrite).
